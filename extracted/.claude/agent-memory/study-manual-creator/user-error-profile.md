用户 2026 期中考 10 道错题（`raw/raw_midterm_wrong/midterm-1~8.png`，题号 4/5/6/8/19/22/25/28/33/35）的根因分布——**错误高度集中，不是随机的**：

- **根因 A（3 次）**：偏好"好处/机制型"选项，放过"负面后果/朴素工程现实"。例：逗号分隔多值列选"简化检索"（正解"使查询低效"）；PostgreSQL 默认 buffer 小选"小缓冲改善 I/O"（正解"为了能在低内存机器上跑"）；页<块选"碎片最小化"（正解"读放大导致性能下降"）。
- **根因 B（3 次，最贵）**：论文类 NOT-correct 题里，**把"含具体数字/系统名/产品名"的陈述当成最可疑**，反而放过"方向反转的顺畅泛论"。实际规律相反：出题人拿论文原话（含数字、Polars/Dask、"a few hundred instructions"）当 TRUE 干扰项，把错误藏在 because/so 型因果断言里。已用 paper2.md / paper3.md 原文逐字验证。
- **根因 E（4 次）**：关系代数 / SQL 语义的定义与顺序不牢——SQL 无 ORDER BY 的顺序、GROUP BY→HAVING→ORDER BY 顺序、π 复合是**交集**不是并集、closure 定义。
- **根因 D（3 次）**：硬件/物理层事实薄弱——DRAM 电容漏电 vs NAND 浮栅、页 vs 块的读放大。
- **根因 C（1 次）**：自己总结过"绝对化措辞是陷阱"，但在**非 NOT-correct 题型**下没启用（选了含 `always` 的选项）。
- **根因 F（1 次）**：同名异义混淆（closure 有关系代数 / attribute closure / lossless-join 三义）。

按知识域：关系模型/关系代数/SQL 语义 **5 题（50%）**；物理存储/缓冲/硬件 **3 题**；论文细节 **2 题**。**索引 / 算子 / C++ 零失误**（这三块是强项）。

**Why:** 这是唯一有真实考试数据支撑的弱点画像，比任何主题猜测都准。用户在 index/operator/C++ 上不需要补救，只需保持。
**How to apply:** 为该用户出题或写指南时：① 每套题里刻意放"朴素实话 vs 漂亮机制"的对照项训练根因 A；② 论文题的错误项一律用"方向反转的因果断言"，正确干扰项用原文原话+数字；③ 关系代数题要求代最小例子验算；④ 补硬件事实小表（介质易失性、三种放大）；⑤ 提醒绝对化词规则对所有题型生效。完整诊断与 6 条应试规则写在 `STUDY_GUIDE/13_期末考试_出题人分析与错题诊断.md` Part 2。
