In this lesson, we will discuss about the limitations
of the page class, such as supporting
variable length tuples. We will then introduce
the idea of slurred pages and how it addresses these
limitations of the page class. In the page class, finding
space for a new tuple requires a linear scan through the entire page to identify
a suitable empty slot. Imagine a scenario where a page is nearly full containing
hundreds of tuples. Inserting a new tuple in
this scenario is similar to searching for a vacant parking
spot in a nearly full lot, as the system scans from the start to find an
appropriate empty slot. If we were to support
variable length tuples, that further complicates
this problem. For instance, storing
text strings of varying lengths in a fixed sized slot model
results in wasted space. Short strings like high waste
almost the entire slot, while longer strings like hello world might
not fit at all. After numerous insertions
and deletions, a page can become
highly fragmented, similar to a Swiss
cheese full of holes. To maintain efficiency, the database system must
periodically compact this page, and that involves moving tupples around the page to consolidate
free space, as shown here. This compaction process adds significant overhead to
the database system. In the next version of Bz DV, the slotted page
class introduces a flexible structure
for managing tuples. Slots or metadata entries in a page header section
that keep track of where the tuples are
stored within the page. Each slot contains the offset, which is the starting
point of the tuple within the page and the length of
the tuple that it stores. There is a free
space offset field in the page header that indicates the starting point of the available free
space within the page. This offset is dynamically updated as tuples are
inserted or deleted. It is followed by
the slot array with all the metadata about the location of the
tuples within the page. The slots follow immediately
after the page header. And they contain the actual
tuples stored in the page. Unlike the page class, slots allow tuples to be
placed anywhere in the page, so it is easy to store variable length
records depending on the first lot
with enough space. Slots also enable direct
access to any tuple by index, thereby facilitating
efficient reads, updates, and deletes without requiring linear scanning or reorganization
of the entire page. A header at the top of
each page tracks metadata, including the number of slots
and the free space offset. Each slot points to the start of that tuples
data within the page. This design naturally supports
variable length tuples. When adding a tuple, the system checks for
available space and identifies the correct slot for the tuple for efficient
space utilization. This code itertes over the slot array to find an empty slot with
sufficient space. The delete method
marks a tuple as deleted within the slot page
by updating the slot array, thereby freeing up space
for future insertions. This approach allows for
efficient space reclamation. For updates that
change the tuple size, the system can either update the tuple in place
if space permits, or it can move the tuple within the page and update the slot with a new
offset and length. This flexibility allows
the database system to handle dynamic data
sizes efficiently. The slotted page
addresses the problem of linear scan for empty
space by checking the page header for a slot with enough contiguous
free space and then directly asking that
slot for tuple addition. It also solves the
problem of supporting variable length
records by allowing each slot to point to
a tuple of any length, thereby minimizing
internal fragmentation. Additionally, compaction is
simplified because tuples can be easily moved around to other slots to compact the page, and only the slot offsets
need to be updated. This approach minimizes
the compaction overhead. To wrap up, in this lesson, we first discussed
the limitations of the page class such as
complicated compaction. We then introduced the
slotted page class, highlighting its
flexible structure that simplifies compaction. The slotted page design
significantly enhances the performance and scalability
of the database system.
