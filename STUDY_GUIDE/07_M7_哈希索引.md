## 📖 三、核心概念精讲

### 3.1 索引（index）—— 为什么快

- **类比**：书的"目录/索引"让你不用一页页翻就能定位。数据库索引让你不用扫全表就能找到行（如"所有 Atlanta 的用户"）。
- index 源自拉丁语 *indicare*（指出、指明）。

**C++ 两种索引容器**：

| | `std::map` | `std::unordered_map` |
|:---|:---|:---|
| 底层 | 平衡二叉搜索树（BST/红黑树） | **哈希表** |
| 顺序 | **有序**（按 key 排序） | **无序** |
| 查找/插入 | **O(log n)** | 平均 **O(1)**，最坏 O(n) |
| 擅长 | 范围查询（如薪资 5000–10000） | 单点快速查找 |

> 💡 选择：要**范围查询/有序**用 `map`；要**最快单点查找**用 `unordered_map`。BuzzDB 自己实现一个哈希表来理解索引内部。

---

### 3.2 ⭐ 哈希表机制（核心）

**类比**：哈希表 = 一排抽屉柜，每个抽屉（slot）放一张写着 (key, value) 的纸。不用挨个翻——用哈希函数直接算出在哪个抽屉。

**哈希函数（hash function）**：把 key 映射成数组下标。简单例子 `key mod 10`（取除以 10 的余数）。

**存（insert）**：
- key=15 → 15 mod 10 = 5 → 放 slot 5（空，直接放）。
- key=26 → 26 mod 10 = 6 → 放 slot 6。
- key=56 → 56 mod 10 = 6 → slot 6 **已占（冲突！）** → 往后找 slot 7 放下。

**哈希冲突（collision）**：两个不同 key 算到同一槽。

**取（retrieve）**：用同一个哈希函数算槽，比对 key：
- 找 56 → slot 6 是 26（不对）→ slot 7 是 56（对！）→ 返回。
- 找 86 → slot 6 是 26 → slot 7 是 56 → slot 8 **空** → **空槽 = 没找到**。

> 🔑 **核心算法**：算初始槽 → 若不是目标 key 就顺序往后探测 → 直到找到 key 或**遇到空槽（= 不存在）**，必要时绕回数组开头。

---

### 3.3 线性探测（linear probing）+ 复杂度 + 聚簇

- **线性探测**：冲突时**逐个**看下一槽，公式 **`(hash(key) + k) mod table_size`**，k = 0,1,2,…（每次 +1）。
- **复杂度**：无/少冲突时 insert/find 平均 **O(1)**；**高冲突时退化到 O(n)**。
- **高冲突来源**：① 占用率高（表快满）② **坏哈希函数**（如总映射到同一槽 → 全挤一处 = **聚簇 clustering**）。
- **主聚簇（primary clustering）**：线性探测让连续被占的槽形成一长串"块"，越长越容易再冲突，雪球效应。如 key 2,12,22,32 都 mod 10=2 → 在 slot 2 起形成连续簇。查不存在的 key（如 31）要遍历整个簇，慢。

---

### 3.4 ⚠️ 删除为什么要"懒删除"（lazy deletion）

- **问题**：直接删一个 key 会在表里留个**空洞**，**破坏探测序列**。
  - 例：32 在 slot 5（因 2,3,4 被占探测过来）。删了 slot 3 的 13 → 留洞。再找 32：slot 2 不是 → slot 3 **空了** → 误判"没找到"！但 32 还在 slot 5。
- **解法**：**懒删除**——给条目加 `exist` 标志，删除时只置 false（标记为已删），**不真删**。这样探测序列不断，遇到"已删"标记继续往后探。
- 用 `std::optional` 优雅表示空槽；为省内存可用**定长数组**代替 vector（vector 扩容要重新分配+拷贝，类似 rehashing）。

---

### 3.5 ⭐ 二次探测 vs 双重哈希（解决聚簇）

| 探测法 | 公式（第 k 次探测） | 解决 | 遗留问题 |
|:---|:---|:---|:---|
| **线性探测** | `hash(key) + k` | — | 主聚簇 |
| **二次探测** | `hash(key) + k²` | 减少**主聚簇**（跳更大间隔） | 仍有**二次聚簇** |
| **双重哈希** | `hash1(key) + k·hash2(key)` | 几乎消除**二次聚簇** | — |

**二次探测（quadratic probing）**：冲突时跳 k² 步（1,4,9,…），间隔越来越大，把簇打散。
- 例：插 2,12,22,32（都 hash=2）：2→slot2；12→2+1²=slot3；22→2+1²(占)→2+2²=6→slot6；32→2,3,6 占→2+3²=11 mod10=slot1。
- **二次聚簇（secondary clustering）**：不同 key 若**初始槽相同**，会走**完全一样的探测序列**（因为都按 +k² 跳）→ 仍可能扎堆。如 2,12,22,32 形成二次簇。

**双重哈希（double hashing）**：用**第二个哈希函数 hash2** 决定步长，**每个 key 的探测序列都不同**。
- 公式 `(hash1(key) + k·hash2(key)) mod table_size`。
- 例 hash2 = `1 + key mod (table_size - 1)`。
- ⚠️ **hash2 必须和 hash1 不同**！否则退化成同样序列，失去双重哈希的意义。
- 例：插 2,12,22,32：hash1 都=2，但 hash2 各不同（12→1+12mod9=4，22→1+22mod9=5，32→1+32mod9=6）→ 落到 slot 6,7,8 等不同位置，**探测步数都很小**，没有长探测序列。

> 🔑 **一句话**：线性探测→主聚簇；二次探测→打散主聚簇但留二次聚簇；双重哈希→**每个 key 独特序列**，几乎消除聚簇。

## 📄 四、配套章节分析

### 📘 ch13 / ch1 索引要点
- **哈希文件组织（ch13 Slide 10）**：哈希函数算 search key → 决定记录放哪个块。
- **二级索引（ch1，测验 Q16）**：flat-file 查找慢，关系库用**二级索引（如 B+Tree）**配成本优化器，选索引扫描而非全表扫描。
- 【补充】B+Tree vs 哈希索引：哈希适合**等值查找**（=）；B+Tree 适合**范围查找**（between）和有序遍历。

## 🧩 五、例题精解

### 例题 1（测验 Q16）— 治"查找慢"的最直接特性
**题**：针对 flat-file 查找慢，关系库哪个特性**最直接**改善检索效率？
- ✅ **正确**：**二级索引（B+Tree）+ 成本优化器**选索引扫描而非全表扫描。
- **考点**：查找慢的直接解药 = **索引**。哈希索引（本模块）和 B+Tree 都是索引结构。

---

### 例题 2（手算）— 线性探测插入
**题**：表大小 10，hash = key mod 10，线性探测。依次插入 5, 15, 25, 7。各落在哪？
- ✅ **解**：
  - 5 → slot 5（空）✓
  - 15 → 5（占）→ 6（空）✓
  - 25 → 5（占）→ 6（占）→ 7（空）✓
  - 7 → 7（被 25 占）→ 8（空）✓
  - 结果：slot5=5, slot6=15, slot7=25, slot8=7。
- **考点**：线性探测冲突就 +1 找下一空槽。

---

### 例题 3（概念）— 懒删除
**题**：上题后，若**直接清空** slot 6（删 15），再查 25 会怎样？为什么要懒删除？
- ✅ **解**：25 hash=5 → slot5=5（不是）→ slot6 **空了** → 误判"25 不存在"！但 25 还在 slot7。**懒删除**（标记 slot6 为 deleted 而非清空）能让查找继续往后探到 slot7 找到 25。
- **考点**：直接删留洞断探测链 → 必须懒删除。

## 🏋️ 六、举一反三 + 新增模拟考题（含答案）

> 🟢基础 🟡进阶 🔴挑战

### A. 选择题

**A1 🟢** `std::map` 和 `std::unordered_map` 的关键区别是？
A) map 用哈希表、unordered_map 用 BST
B) map 有序 O(log n)、unordered_map 无序平均 O(1)
C) 两者完全一样 D) unordered_map 支持范围查询更好
<details><summary>答案</summary>**B**。map=红黑树(有序,O(log n))；unordered_map=哈希表(无序,平均O(1))。范围查询反而 map 好。</details>

**A2 🟡** 哈希查找时遇到**空槽**意味着什么？
A) 表满了 B) 哈希函数坏了 C) 要找的 key 不存在 D) 发生了冲突
<details><summary>答案</summary>**C**。探测过程中遇空槽 = key 不在表里（因为若存在，它会被放在探测路径上某个非空槽）。</details>

**A3 🟡** 二次探测相比线性探测主要解决什么？还留下什么问题？
<details><summary>答案</summary>二次探测（+k²）跳更大间隔，**减少主聚簇**；但不同 key 若初始槽相同会走相同探测序列，仍有**二次聚簇**。</details>

**A4 🔴** 双重哈希中，为什么 hash2 必须和 hash1 不同？
<details><summary>答案</summary>双重哈希靠 hash2 给每个 key 不同的探测步长，从而每个 key 有**独特探测序列**消除聚簇。若 hash2=hash1，所有同初始槽的 key 又走相同序列，退化回二次聚簇，失去意义。</details>

### B. 判断题

**B1 🟢** "哈希表插入/查找在无冲突时平均 O(1)，但高冲突时会退化到 O(n)。"
<details><summary>答案</summary>**对**。坏哈希或高占用率导致聚簇 → O(n)。</details>

**B2 🟡** "从哈希表删除 key 时，应该直接把那个槽清空。"
<details><summary>答案</summary>**错**。直接清空会留洞断探测链，导致后续 key 误判不存在。应**懒删除**（标记 deleted）。</details>

**B3 🔴** "线性探测和二次探测都可能产生聚簇，但聚簇类型不同。"
<details><summary>答案</summary>**对**。线性→主聚簇（连续块）；二次→二次聚簇（同初始槽走相同序列）。</details>

### C. 简答题

**C1 🟡** 表大小 7，hash = key mod 7，线性探测。依次插入 10, 17, 3, 24。写出每个 key 的落点。
<details><summary>参考答案</summary>10→10mod7=3 (空)→slot3；17→17mod7=3(占)→slot4；3→3mod7=3(占)→4(占)→slot5；24→24mod7=3(占)→4,5(占)→slot6。结果 slot3=10,4=17,5=3,6=24。</details>

**C2 🔴** 用一句话总结线性探测→二次探测→双重哈希的演进逻辑。
<details><summary>参考答案</summary>线性探测简单但产生主聚簇（连续块）；二次探测用 k² 跳跃打散主聚簇，但同初始槽的 key 仍走相同序列产生二次聚簇；双重哈希用第二个哈希函数给每个 key 独特步长，使探测序列各不相同，几乎消除聚簇。</details>

### D. 应用题

**D1 🔴** 表大小 10，hash1 = key mod 10，hash2 = 1 + (key mod 9)，双重哈希。插入 19，若 slot 9 已被占，下一个探测槽是哪个？
<details><summary>参考答案</summary>hash1(19)=9（占）。hash2(19)=1+(19 mod 9)=1+1=2。k=1：(9 + 1×2) mod 10 = 11 mod 10 = **slot 1**。所以探测 slot 1。</details>

## ⭐ 七、易错点 & 速记

| 易错点 | 正确理解 |
|:---|:---|
| map / unordered_map 搞反 | map=BST有序O(log n)；unordered_map=哈希O(1) |
| 哈希删除直接清空槽 | 要**懒删除**（标记 deleted）保探测链 |
| 以为二次探测消除所有聚簇 | 只消主聚簇，留二次聚簇 |
| 双重哈希 hash2 = hash1 | hash2 **必须不同**于 hash1 |
| 探测遇空槽继续找 | 空槽 = key 不存在（停止） |

**🎵 口诀**：
- 容器：**"map 树有序、unordered 哈希快"**
- 探测演进：**"线性主聚簇、二次留二次、双哈各不同"**
- 删除：**"懒删标记不留洞"**
- 公式：线性 `h+k`、二次 `h+k²`、双哈 `h1+k·h2`
