## 选择题

**1. C** — 声明式 SQL 查询是**关系模型**的优点，不是 flat-file 的问题。A/B/D 都是 flat-file 的真实局限。

**2. C** — 错！SQL 的 `SELECT 列名` 对应**投影 Π**，不是选择 σ；σ 对应 `WHERE`。这是最经典的术语陷阱。

**3. C** — 多对多关联表用**复合主键 (StudentID, CourseID)**，单列做主键会限制每个学生/课程只能一行。

**4. C** — 错！长扫描分析事务是 **OLAP**，不是 OLTP。OLTP=短平快点操作。

**5. D** — Codd 要消除排序/索引/访问路径依赖。"网络带宽依赖"是编造的。

**6. B** — 原子性 = 全做或全不做。A 是一致性、C 是持久性、D 是隔离性。

**7. C** — 无隔离 → 脏读/不可重复读/丢失更新/幻读。A/B/D 张冠李戴。

**8. B** — 静态类型编译期绑定类型 → 代码特化（定长 tuple 布局）。A/C/D 都错。

**9. C** — 错！DRAM 比 SSD **贵得多**（~$10/GB vs ~$0.10/GB），不是便宜。

**10. B** — 序列化必须显式写值 + 加载时重建。传 unique_ptr 不会自动序列化（A 错）；裸指针跨运行无效（C 错）；unique_ptr 不决定磁盘格式（D 错）。

**11. B** — 错！深拷贝**不共享**缓冲区，它给每个对象独立副本（更费内存、更安全）。共享是浅拷贝。

**12. C** — 错！`stoi("100abc")` **不抛异常**，它解析出 100、忽略 "abc"。所以它不能严格拒绝尾随字符；`from_chars` 才能。

**13. B** — 内存用指针动态增长，磁盘线性化成带长度字节流，裸指针无意义。A/C/D 都误以为指针能存盘。

**14. C** — 错！槽页**不保证**原地增长——元组变大放不下要移动并更新槽。

**15. C** — 错！`reinterpret_cast` **不可移植也不安全**，是危险的位级重解释。

**16. B** — 错！定位 I/O 的价值是 **API 清晰**（显式 offset/length、无共享流状态），**不是性能**——省那点函数调用对性能微不足道。

**17. B** — 缓冲管理器缓存热页、最小化磁盘 I/O。

**18. B** — 错！多态指针正是为**运行时**换策略（指针重指向），无需重新链接。

**19. C** — 错！`=0` 是纯虚函数 → **抽象类 + 运行时 vtable 分派**，反而**有**虚调用开销，不是编译期绑定。

**20. A** — 错！SSD 仍比 DRAM 慢，**缓冲池大小依然重要**。

**21. C** — 错！这正是 Stonebraker 指出 OS **缺失**的功能——OS 缓冲管理器**不**提供"选择性强制写出"，所以 DBMS 要自建。

**22. B** — 错！mutex 只保证**互斥**，**不保证公平**。

**23. B** — `+= 10` 是 load/add/store 三步，非原子，可被打断 → 丢失更新。

**24. C** — 错！page_size **不可变**，改它要 dump+reload（影响磁盘布局）。

**25. B** — 并发线程读写共享计数器要原子防 data race。A/C/D 都是编造的。

**26. D** — 错！unordered_map 平均 O(1) 但**最坏 O(n)**（高冲突/聚簇），不保证 O(1)。

**27. B** — 懒删除（标记 deleted）保探测序列。直接清空会留洞断链。

**28. C** — 错！hash2 **必须不同**于 hash1，否则退化成相同探测序列、失去意义。

**29. B** — 错！OS **不会** panic。真正危险是数据竞争导致的逻辑错误/损坏（TOCTOU）。

**30. B** — mutex 不可移动，vector 扩容要移动元素 → 用 `unique_ptr<mutex>`，只移动指针。

## 计算题

**31.** IOPS ∝ 1/延迟。比值 = 10 ms / 100 µs = 10000 µs / 100 µs = **100 倍**。

**32.**
- A：吞吐 ∝ 1/200ns = 5×10⁶ ops/s = 5 Mops；性价比 = $800/5 = **$160/Mops**。
- B：吞吐 ∝ 1/500ns = 2×10⁶ ops/s = 2 Mops；性价比 = $250/2 = **$125/Mops**。
- **B 更划算**（$125 < $160）。
- ⚠️ 注意：这题和 M3 例题不同——这里 **B 更好**。要老老实实算，别套结论！

**33.**
- (a) (8192−64)/128 = 8128/128 ≈ **63.5 ≈ 64 个元组**。
- (b) 平均扫 64/2 = **32 个**；延迟 = 32 × 0.05 = **1.6 µs**。
- (c) 无槽：10⁶ × 1.6µs = 1.6 s CPU/s → **1.6 核**；有槽：10⁶ × 0.20µs = 0.2 s CPU/s → **0.2 核**。

**34.** 序列 1,2,3,2,4,1,5,2（容量 3，括号=最近→最久）：
- 1 miss(1)；2 miss(2,1)；3 miss(3,2,1)；2 hit(2,3,1)；4 miss 踢1 (4,2,3)；1 miss 踢3 (1,4,2)；5 miss 踢2 (5,1,4)；2 miss 踢4 (2,5,1)。
- **共 7 次 miss**（1 次 hit）。

**35.** 表大小 10，hash=key mod 10，线性探测：
- 14 → 14 mod 10 = 4（空）→ **slot 4**
- 24 → 4（占）→ 5（空）→ **slot 5**
- 34 → 4（占）→ 5（占）→ 6（空）→ **slot 6**
- 5 → 5（被 24 占）→ 6（被 34 占）→ 7（空）→ **slot 7**
- 结果：slot4=14, slot5=24, slot6=34, slot7=5。

## 简答题

**36.** 数据独立性 = 应用只依赖**逻辑设计**（表/列/键），不依赖**物理设计**（存储格式/索引/硬件）。所以 DBA 能改物理设计（换索引、升级存储）而**不影响应用代码**。它是关系模型核心优势，因为让数据库能随负载和硬件演进而不打断上层业务（Codd Paper 1 全文核心）。

**37.**
- **A 原子性**：转账两笔（A 扣、B 加）要么都成要么都不成。
- **C 一致性**：转账前后总额守恒，从合法态到合法态。
- **I 隔离性**：另一并发转账看不到本次的中间态，不互相覆盖。
- **D 持久性**：转账一旦提交，即使断电也不丢。

**38.** **缓冲池 flooding**：顺序扫描（全表扫）读入大量"扫一次就不用"的冷页，LRU 把它们当"最近使用"留下，挤掉真正反复用的热页 → 热页反复 miss。**2Q 解法**：用两个队列——FIFO 队列放"扫一次"的冷页（新页先进这里），LRU 队列放热页（页第二次被访问时晋升过来）；**驱逐时优先踢 FIFO 队列**保护 LRU 里的热页。这样顺序扫描的冷页被优先驱逐，热页留在缓存。

**39.** 至少两个理由（任选）：
① **LRU 不适合 DB 访问模式**——顺序扫描时该 toss-immediately，但 OS 只会 LRU；
② **预取方向不对**——DBMS 知道下一个真正要读的块（不一定是文件里下一块），OS 无法正确预取；
③ **缺选择性强制写出**——崩溃恢复需要 commit 标志在 intentions list 之后刷盘，OS 缓冲管理器不提供；
④ **取块开销大**（系统调用 + core-to-core 拷贝，上千条指令）。

**40.** PageGuard **move-only** 是为了保证**唯一所有权**（像 unique_ptr）——一个被 fix 的页同一时刻只能有一个 guard 负责 unfix 它。若允许拷贝，两个 guard 指向同一帧，析构时会 **unfix 两次**（双重释放：减两次 pin 计数、解两次锁）→ 错误。move 时把旧对象的 `frame_` 置空，是为了让 **moved-from 对象析构时不再调 unfix_page**（因为所有权已转移给新对象），否则同样会双重 unfix。这与测验 Q20 的竞态/双重释放主题一脉相承。
