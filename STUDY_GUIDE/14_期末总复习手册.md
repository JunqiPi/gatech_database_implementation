## A.4 ⭐⭐ 6 条应试行为规则（针对你期中错题的根因，考前抄在草稿纸上）

1. **绝对化词无条件预警** —— 不管题型是正问还是反问。（你在"Will the order change?"里选了含 `always` 的选项。）
2. **论文 NOT-correct 题：反过来用"具体性"判断** —— **含具体数字/系统名/产品名的 = 大概率原文原话 = 大概率为真**；错误项通常是**带 because/so 的、顺畅的、方向反了的泛论**。（你两次拒掉了论文原话。）
3. **选"最不炫技的实话"** —— 一个选项是朴素的负面后果/工程现实、其余是漂亮机制时，朴素那个通常是答案。
4. **关系代数带公式的题：代 2×2 最小例子验算** —— 尤其检查复合是"交"还是"并"、是否需要子集前提。
5. **同名异义先归属再作答** —— closure / projection / delta / merge / flow control / partitioning 都有 ≥2 义。
6. **计算题先算完写下中间量，再看选项** —— 绝不先扫选项再"凑"。

## B.1 ⭐⭐⭐ 关系模型与关系代数（你的最大失血点：5/10 错题）

### 必背定义（期中 Q33 考的就是这些）
| 概念 | 精确定义 |
|:---|:---|
| **domain（域）** | 原子值的集合，**至少定义了相等比较**（否则没法做选择/连接/去重） |
| **tuple（元组）** | 从**属性名**到**各自域中的值**的一个**函数**（这是"属性无序、靠名字引用"的形式化根据） |
| **relation（关系）** | 域的**笛卡尔积的子集**；**属性是域上的具名角色（named roles）**，所以**同一个域可以在不同属性名下出现多次**（例：`Flight(origin: City, destination: City)`） |
| **closure（闭合性）** | ⭐ **关系算子的输入是关系、输出也是关系** → 因此**可以任意嵌套组合**。这正是"关系查询天然可组合成 dataflow graph"（P8）和"iterator 可任意拼接"（P9）的根据 |

### ⭐ 关系代数性质（期中 Q33 的核心，必须会验算）
```
π_X(π_Y(R)) = π_{X ∩ Y}(R)         ← 【交集】不是并集！
且要求 X ⊆ Y 才有定义（否则 X 里的属性已经不存在了）
⇒ 投影【不可交换】：π_X(π_Y(R)) 要 X⊆Y，π_Y(π_X(R)) 要 Y⊆X
```
> 💡 **直觉**：投影只会**越投越少**，不可能凭空造出属性。
> 💡 **验算法**：`R(A,B) = {(1,x),(2,y)}`，X={A}, Y={B} → `π_B(R)={(x),(y)}` 里**没有 A** → `π_A(π_B(R))` 不合法，立刻判死。

**其他常考性质**：
- **σ 可交换、可下推**：`σ_p(σ_q(R)) = σ_q(σ_p(R)) = σ_{p∧q}(R)` ✅（**σ 才是并集式合并，π 是交集式**——最容易混）
- ⭐ **集合语义下投影要去重** → **投影掉所有候选键的属性会把不同元组压成一条** → **键不被投影保持**。例：`R(id, city)` 三行不同 id 都是 Atlanta，`π_city(R)` 只剩 1 行。
- **σ 与 π 的顺序**：`π_X(σ_p(R)) = σ_p(π_X(R))` **仅当 p 只引用 X 里的属性**。

### ⭐⭐ closure 的三种同名异义（期中 Q35 考点）
| 说法 | 属于 | 含义 |
|:---|:---|:---|
| **Closure（关系代数）** | ch2 | 算子输入输出都是关系 → **可组合** |
| **Attribute closure X⁺** | 函数依赖/范式化 | 由 X 通过 FD 能推出的全部属性 |
| **Lossless-join decomposition** | 范式化 | 分解后能通过 join 无损还原 |

### 范式化 / 1NF（期中 Q4 考点）
- **1NF** = 所有属性都是**原子值**。Codd P1 叫消除 **non-simple domain（非简单域）/ 嵌套域**；**normalization 的定义就是"消除非简单域、产出扁平关系"**。
- ⭐ **把多值塞进一列（逗号分隔）的后果全是负面的**：无法用索引、无法 join、无法加外键约束、排序/聚合/去重全失效。
- **规范化收益的标准表述**（S1-Q12 正解）：*"Eliminate repeated user attributes from Posts/Interactions by storing them once in Users and relating via foreign keys, **preventing update anomalies**."*
- **键设计**（S1-Q21/Q35 两次考）：多对多关系表 `Enrollments(StudentID, CourseID)` 必须用**复合主键 (StudentID, CourseID)**，两列各自是外键。单列主键存不下"一个学生选多门课"。

## B.2 ⭐⭐ SQL 语义与求值顺序（期中 Q6、Q25）

### 必背：SQL 逻辑求值顺序
```
FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT(投影/别名) → DISTINCT → ORDER BY → LIMIT
              ↑                    ↑
          过滤【行】          过滤【组】
```
- 💡 **WHERE 过滤行（分组前），HAVING 过滤组（分组后），ORDER BY 永远最后。**
- 💡 **副作用**：`SELECT` 的别名在 `WHERE/GROUP BY/HAVING` 之后才产生 → **标准 SQL 不能在 WHERE 里用别名，但能在 ORDER BY 里用**。

### ⭐ 无 ORDER BY 则顺序不保证
关系是**无序的元组集合**（Codd 要消灭的三种依赖之一就是 **ordering dependence**）。实际顺序取决于：访问路径（全表扫 vs 索引扫）、缓冲池状态、并行度、优化器当次的计划、vacuum/更新导致的物理重排。

## B.3 ⭐⭐ 存储介质与硬件事实（期中 Q22）

| 介质 | 易失性 | 物理机制 | 用在哪 |
|:---|:---|:---|:---|
| **SRAM** | 易失 | 触发器（6 晶体管锁存），**不需刷新**，最快最贵 | CPU cache |
| **DRAM** | ⭐ **易失** | ⭐ **电容 + 需周期刷新（典型 64 ms）**，电容漏电 → "Dynamic" 就指这个 | 主存 / 缓冲池 |
| **NAND Flash** | ⭐ **非易失** | ⭐ **浮栅晶体管**困住电荷；**写前需擦除** → **随机写慢于顺序写** | SSD |
| **HDD** | 非易失 | 磁化盘片 + 机械寻道 | 冷数据 |

**典型延迟数量级（IOPS 计算题的地基）**：
| 层级 | 延迟 |
|:---|:---|
| CPU L1 cache | ~1 ns |
| DRAM | ~100 ns |
| SSD 随机读 | ~80–100 μs |
| HDD 寻道+旋转 | ~8–10 ms |
| 网络（同数据中心） | ~0.5 ms |

## B.4 ⭐⭐ 页 / 块 / 三种放大（期中 Q28）

| 术语 | 定义 | 典型起因 |
|:---|:---|:---|
| **Read amplification** | 实际读字节 / 真正需要的字节 | ⭐ **页 < 块**（读 1KB 页要拉整个 4KB 块 → 4× 读放大）；LSM 查多层；Bw-tree 的 delta 分散 |
| **Write amplification** | 实际写字节 / 逻辑写字节 | ⭐ **页 < 块**（read-modify-write）；日志结构存储的 GC 搬运活数据；flash 擦除块粒度 |
| **Space amplification** | 实际占空间 / 逻辑数据大小 | 旧版本未回收；B+树节点半满；⭐ **C-Store 的 overlapping projections（故意的）** |

> ⭐ **交叉点**：P5 Bw-Tree 的"**增量刷盘减少写放大，代价是读放大**"——它靠 **flash 极高的随机读性能**偿还读放大。

## B.5 槽页 Slotted Page（S1 考了 3 次）

**结构**：页头 + **slot directory（槽目录）**（slot ID → (offset, length)）从前往后长；**元组数据从后往前长**；中间是空闲空间。

| ✅ 正确性质 | ❌ 常见陷阱 |
|:---|:---|
| 逻辑删除：**标记 slot 空闲，不必立刻物理移动其他元组** | ❌ "**槽目录保证元组能原地增长而无需重定位**"（S1-Q11 错——元组变大装不下就得**搬走**，slot 里换成新 offset 或 forwarding pointer） |
| **页压缩（compaction）时元组可移动，slot ID 对上层保持稳定** | |
| 多一层间接**略增查找成本**，但**远低于扫描变长记录数组** | |
| 元数据写在**尾部且无头部指针** → ⭐ **读者必须扫/seek 到末尾才知道元组数，使反序列化复杂化**（S1-Q3） | |

## B.6 缓冲管理器（S1 考了 3 次 + 期中 Q19）

- **策略多态**：`AbstractPolicy` 声明 `virtual void touch(PageId); virtual PageId evict() = 0;`
  - ⭐ `= 0`（纯虚）→ 类**抽象、不能实例化**；派生类必须实现才具体；**调用走运行期 vtable 分派**，**不是编译期绑定**（S1-Q18 高频错点）。
  - ⭐ **策略可在编译期和运行期都替换**（S1-Q24 正解 "Both"）。
- **pin/unpin、dirty flag、写回**：内存改动**只有在页被写回或被缓冲管理器刷出后才持久**；⭐ **不是每次删除都要立刻 fsync**（S1-Q19 的绝对化陷阱）。
- ⭐ **PostgreSQL 默认 shared buffer 只有 128 MB 的原因 = 为了能在低内存机器上开箱即用**（不是"小缓冲更高效"）。生产建议约为物理内存的 25%。
- **SSD 上的缓冲优先级**（S1-Q5）：缓存热页**仍然重要**（SSD 仍慢于 DRAM）；顺序预取**变得不那么关键**；批量刷脏页**能减少写放大、延长 SSD 寿命**；⚠️ ❌"缓冲池大小的配置不像 HDD 时代那么关键"是**错的**。

## B.7 C++ / BuzzDB 实现（S1 占 40%，期末仍会考）

| 考点 | 必须能一句话说清 |
|:---|:---|
| **RAII / unique_ptr** | 异常抛出时**栈展开自动析构**，**不需要手动 delete[]**；移动后由新 owner 释放 |
| **序列化 vs 指针** | ⭐ **传/移动一个 unique_ptr 进写函数并不会序列化它指向的数据**；必须写**值**（len + 字节流）并在加载时**重建新缓冲区**；**写指针值跨运行毫无意义** |
| **深拷贝** | 每个对象**独立数据**，避免意外共享；❌ **不会"通过共享缓冲区节省内存"**（正好相反） |
| **reinterpret_cast** | 让危险转换**显式化、可审计**；只做重新解释、不混入 const_cast/static_cast；❌ **不是"只要大小匹配就可移植且安全"** |
| **from_chars vs stoi** | `from_chars` **不抛异常、不分配内存**，返回**指向第一个未解析字符的指针** → 可严格校验尾部无杂字符；❌ **`stoi` 不会拒绝 "100abc"**（它会静默解析出 100） |
| **std::atomic** | 例：`num_pages` —— **一个线程扩展文件的同时另一个线程读它做边界检查** |
| **虚函数 vs 模板** | 虚函数 = **运行期 vtable**；模板 = **编译期实例化** |
| **封装的量化收益** | `PAGE_SIZE` 私有化 → 改动只影响 **1 个模块**；全局宏 → 影响**全部 5 个模块** |
| **CSV 解析多读一次 getline** | ⭐ 为了**严格执行 schema：检测并拒绝字段数超预期的行** |

## B.8 ⭐⭐⭐ 哈希索引（Final Practice Q3 直接命中，必须会算）

**开放寻址三种探测**：
| 方式 | 探测序列 |
|:---|:---|
| **线性探测** | `(h(k) + i) mod m` |
| **二次探测** | `(h(k) + c₁i + c₂i²) mod m` |
| ⭐ **双重哈希** | `(h₁(k) + i · h₂(k)) mod m`，**i 从 0 开始** |

> ⭐ **必须逐步写出探测序列**，不要退化成线性探测——这是官方 Final Practice 的诱饵。
> **懒删除（lazy deletion）**：删除要留 **tombstone（墓碑标记）**，否则会截断后续键的探测链。
> ⭐ **哈希索引不支持范围查询的原因是"键不按顺序存放"，不是"哈希函数慢"。**

**C++ 容器对照（Sheet 02 例题 2 直接考过）**：
| 容器 | 底层 | 查找复杂度 | 有序？ | 范围查询 |
|:---|:---|:---|:---:|:---|
| `std::map` | **红黑树** | O(log N) | ✅ 有序 | ✅ 支持 |
| `std::unordered_map` | ⭐ **哈希表** | ⭐ **平均 O(1)** | ❌ 无序 | ❌ 不支持 |

### C.1.1 结构事实（一字不差）
```
                 [ 20 ]                  ← 根（也是内部节点）
               /        \
        [5 | 11]        [23 | 25]        ← 内部节点：只有分隔键 + 子指针
       /   |    \       /   |   \
   [1,2] [5,7] [11,17] [20,21] [23,24] [25,30]   ← 叶子：键 + 真实值/RID
     └──→──┴──→──┴──→──┴──→──┴──→──┘     叶子间有兄弟指针
```
| 事实 | 内容 |
|:---|:---|
| **内部节点** | ⭐ **键数 = 子指针数 − 1**；只有分隔键和子指针，**payload 只在叶子**；**内部键可以与叶子键重复** |
| **叶子** | 键数 = 值数；有**兄弟指针**支持范围扫描 |
| ⭐ **精确查找** | **必须走到叶子**，即使查找键等于某内部分隔键**也不能提前终止**（"能提前终止"是 **B-tree** 的性质，不是 B+树）——**Sheet 02 例题 1 的答案** |
| **占用率（n 路）** | 内部：⌈n/2⌉–n 个孩子；叶子：⌈(n−1)/2⌉–(n−1) 个值；**根 ≥ 2 个孩子**（除非它是叶子） |
| **高度** | ≤ ⌈log_⌈n/2⌉(K)⌉；例：n=100, K=10⁶ → 4 |

### C.1.2 插入/分裂/删除机制
- **叶子分裂**：⭐ **分隔键"复制"上去**（叶子仍保留该键）。
- **内部分裂**：⭐ **中位键"搬移"上去**（本节点不再保留）。
- **根分裂** → 新根 1 键 2 孩子，⭐ **树高 +1 且所有路径同时加高**（B+树永远平衡）。
- **删除**：⭐ 若删掉叶子的**最小键**，**父节点的分隔键可能要改成新的最小键，并沿最左边界向上级联**（Sheet 02 例题 1 选项 A）；借用/合并后根只剩 1 个孩子 → **删根，高度 −1**。

### C.1.3 磁盘化 B+ 树（BuzzDB 实现细节）
- 节点大小 = **8m + 13 字节** → **4 KB 页 m = 510**；**16 KB 页 m = 2046**。
- 容量数量级：fanout 510 → **3 层 ≈ 1.3 亿键；4 层 ≈ 670 亿键**。
- ⭐ **序列化时内存指针必须换成文件偏移**。
- 节点内查键用 `std::lower_bound` / `std::upper_bound`：⭐ `lower_bound` = **第一个 ≥ key**；`upper_bound` = **第一个 > key**。
- ⭐ **节点内二分的中点必须写 `mid = l + (h - l)/2`**（`(l+h)/2` 有**整数溢出**风险 —— 这是 JDK binary search bug，**Final Practice Q5 直接考**）。

### C.1.4 叶页布局：inline 记录 vs 指针（Final Practice Q4）

|:---|:---|:---|

### C.2.4 学习索引（+ 论文 P7）
- 核心等式：⭐ **position = F(key) × N**，F 是 **CDF（累积分布函数）**。
- **RMI（递归模型索引）**：分阶段，⭐ **上一阶段的输出用来挑下一阶段的模型**，最后一阶段预测位置；⭐ **阶段之间没有搜索**；⭐ **同阶段模型不必覆盖等大键范围**（不像 B 树节点）。
- **误差处理**：存 min/max error，在界内做**局部搜索**（模型偏置二分 / 偏置四元搜索 pos−σ, pos, pos+σ）。
- ⭐ **hybrid index**：叶模型误差超阈值就**换成 B-Tree** → **把最坏情况兜到 B 树水平**。
- **线性回归公式（会算）**：`slope = Σ(x−x̄)(y−ȳ) / Σ(x−x̄)²`；`intercept = ȳ − slope·x̄`。
- ❌ **不要求键均匀分布**（均匀了反而不需要模型）；❌ **模型不需要预测精确位置**。

### 查询解析（Query Parsing）
- ⭐ **4 个正则**：① 被选属性下标 ② sum 操作 ③ group by 子句+属性下标 ④（较复杂）where 子句谓词的提取与验证。

- **execute_query 流程**：scan → （有 where）每条件建 SimplePredicate、用 ComplexPredicate 组合成 AND、嵌进 Select → （有 sum/group by）实例化 HashAggregation → 从 root `open()` 开始不断 fetch，⭐ **root 递归调用 child 直到叶子算子（scan，无 children）**。
- ⭐ **解析只解决灵活性，运行时开销一点没减。**

### ⭐⭐ 查询解释的 4 个开销来源（最可能考）
| # | 类别 | 开销 |
|:--|:---|:---|
| 1 | compute | **每 tuple 穿过多个算子 → 若干次函数调用**（百万级 tuple 时显著） |
| 2 | compute | **每 tuple 用"通用 schema 假设"反序列化** |
| 3 | compute | ⭐ **多态的动态分派 → 额外查 vtable**（用的是指向抽象类的指针） |
| 4 | ⭐ **memory** | **算子里频繁创建/销毁临时对象**（如指向 field 的 unique_ptr） |

### ⭐⭐ 查询编译（Query Compilation）
- **定义**：把 SQL 串翻译成**硬编码的 C 函数**，再**生成汇编代码**，直接跑机器码。
- **做法**：**离开算子框架**，**在一个函数里**从 scan 干到 aggregation；直接用 buffer manager 遍历所有页/slot；⭐ **把 tuple data 当 raw character string，直接反序列化第一个 field 成整数**——**超快但非常刚性**。
- ⭐ **必背数字：对这个 grouping-based aggregation 查询，编译版比解释版快 30 倍。**
- **优点 2 条**：省去逐 tuple 解释与穿越算子（省 compute + memory）；**跑在 bare metal 上**。
- ⭐ **缺点 2 条**：① **编译本身耗时** —— **查询执行时间很短时，编译+运行可能比直接解释还慢**；② **灵活性差** —— schema 变了要**重新编译**，**频繁重编译的代价可能超过收益**。

## C.6 ⭐⭐⭐ 列存 + 压缩 + 向量化 SIMD（module_12，最高优先级）

### C.6.1 行存 vs 列存
| 维度 | 行存 (NSM) | 列存 (DSM) |
|:---|:---|:---|
| **存储** | 一行所有列存在一起 | ⭐ **每列存在单独的文件** |
| **理想负载** | **事务型**，频繁访问完整记录 | **分析型**，只需列的子集 |
| **最佳访问模式** | 访问**完整的行** | 访问**特定的列** |
| **压缩潜力** | ⭐ **有限**（一行内值类型各异） | ⭐ **高**（每列单一数据类型） |

- **weather 案例**：4 列（timestamp/temperature/humidity/wind speed），查 timestamp 5–75 的平均温度 → **行存读 7 页，列存读 4 页**。
- 合成数据：**100 万行 × 4 列，4 KB 页**；timestamp **顺序递增**、temperature **正态分布**、humidity/wind speed **均匀分布**。
- ⭐ **列存查询 = 两阶段（late materialization 的教学版）**：先扫 timestamp 页 → **合格记录的 offset 存进 map** → **再用 offset 只取需要的 temperature 页**。
- ⭐ **必背数字：高选择性过滤下列存比行存快 30 倍，因为读的页少 4 倍。**（⚠️ **"highly selective filter" 是限定条件，不是无条件 30×**）

### C.6.2 ⭐⭐ 压缩四算法（必背二分：numeric vs categorical）
| 算法 | 数据类型 | 机制 | 关键数字 |
|:---|:---|:---|:---|
| ⭐ **Delta encoding** | **numeric，增量式变化** | 存第一个完整值 + 后续存**与前值的差** | 典型用于 **timestamp**；实现用 `std::adjacent_difference` |
| ⭐ **Bit packing** | **numeric，范围小** | **只分配必要的 bit 数** | 温度 35/40/45/50 落在 **6 bit（0–63）**；原本 **32 bit** |
| ⭐ **Huffman** | **categorical**（字符串） | **基于频率**：高频短码、低频长码 | product ID 出现 **100 次 → 码 `0`**；出现 **10 次 → 码 `111`**。建树时**高频留上层** |
| ⭐ **Byte dictionary** | **categorical，唯一值有限** | 换成**单字节码 0–255** + **反向字典**解码 | — |

⭐⭐ **压缩方案的查询性能（反直觉，极适合出题）**：
| 方案 | 耗时 | 原因 |
|:---|---:|:---|
| 无压缩 | **7.79 ms** | 原始 product ID 要**完整字符串比较** |
| Huffman | **2.24 ms** | 短码，**但仍需按位解码，有额外开销** |
| ⭐ **Byte dictionary** | ⭐ **0.71 ms（最快）** | **单字节比较，极快** |
> ⭐ **结论：压缩比最高 ≠ 查询最快。解码成本才是查询时的瓶颈。** 且**所有算法结果完全一致（无损）**。

### C.6.3 ⭐⭐⭐ 向量化执行 + SIMD
**tuple-at-a-time 的 3 个问题**：① 每 tuple 触发算子间**函数调用**；② **CPU 无法利用一次处理多 tuple 的能力**；③ 常导致 **pipeline stall 和 cache miss**。

⭐ **vector-at-a-time 的收益**：*"Batching reduces function call overhead because we only transition between operators **once per batch rather than once per tuple**."*
> ⭐⭐ **这一句就是 Final Practice Q6 的原理：被摊薄的只有"控制/算子转换"开销，谓词求值成本不变 → 加速比有硬上限。**

**SIMD 的 3 个数据库用例**：① 过滤范围内的行 ② 聚合（sum/avg）③ ⭐ **解码压缩数据（如 bit-packed 列）**。
**核心 3 类操作**：① 加载数据向量 ② 应用 **mask** ③ **horizontal reduction**。

⭐ **过滤流程（ARM NEON 命名）**：
```
vld1q_s32 → 载入 4 个连续 32 位整数
vcgeq_s32 → 比较 ≥ start      ┐ 两个 mask
vcleq_s32 → 比较 ≤ end        ┘
vandq     → 按位 AND 合并 → 范围内的 mask
```
例：载入 **18, 40, 25, 15**，条件 >20 且 <30 → ⭐ **唯一合格的是 25**。

⭐ **求平均温度的完整流程（"用 mask 代替分支"）**：
```
① vload 整数/浮点各 4 个
② 两次比较 → 两 mask → AND 合并
③ ⭐ mask 转 float，用 vmulq 逐元素相乘 → 范围外变 0，范围内保留原值
④ vaddq 加到运行中的 sum 向量
⑤ horizontal reduction（vaddvq）→ 标量和
⑥ ⭐ 标量循环处理剩余元素（总数非 4 的倍数时）——"SIMD 算法的常见模式"
```

⭐⭐ **SIMD 三大优势**：
| # | 优势 | 要点 |
|:--|:---|:---|
| 1 | **指令数减少** | ⭐ **N 个数据点、向量宽度 W → 只需 N/W 条指令**；还降低**指令解码和调度**开销 |
| 2 | **内存访问规整** | 连续数组（**列式尤其**）→ **向量加载与 cache line 对齐**，充分利用每次内存传输；⭐ **分散/行式访问导致 cache line 部分利用 + 更多 cache miss** |
| 3 | **最小化分支** | ⭐ **依赖 mask 而不是分支** → 避免误预测导致的 **pipeline stall** |

⭐ **SIMD 历史与命名**：
| 时期 | 技术 |
|:---|:---|
| 早期超算 | **ILLIAC IV**（矩阵乘法） |
| **1996** | ⭐ **Intel MMX**（桌面 CPU 的并行整数运算，例：图像加亮度） |
| 2000s 早期 | ⭐ **Intel SSE / ARM NEON，都是 128 位**，支持浮点 |
| 2010s | ⭐ **Intel AVX-512 → 512 位** |
| 现代 | ⭐ **Apache Arrow**（**列式**内存格式，大规模利用 SIMD） |

- **SoA（Structure of Arrays）**：拆成独立数组 → 每列连续、适合向量加载；**按 SIMD 友好边界对齐防止 misaligned access**。
- **命名约定** = 操作类型 + 数据类型 + 向量宽度；⭐ **`Q` = quad-word = 128 位**（`vld1q_s32` = 载入 4 个 32 位有符号整数；`vaddq_f32` = 4 个 float 相加）。
- **SIMD hash join**：载入一批 probe key → 并行算 hash → ⭐ **从哈希表 gather（查找不连续，需专门的 gather 指令）** → 向量比较找匹配。⭐ **"非连续访问有挑战，但好的数据布局仍能提升"**。

## C.7 ⭐⭐⭐ ch15 查询处理与代价模型（计算题主战场）

### 查询处理三步曲
**parsing & translation → optimization → evaluation**

### 代价度量
⭐ **代价 = b·t_T + S·t_S**（b = 块传输数，S = 寻道数）；**HDD 典型：t_S = 4 ms，t_T = 0.1 ms**。

### 选择算法
| 算法 | 场景 | 代价 |
|:---|:---|:---|
| **A1** 线性扫描 | 无索引 | b_r 传输 + 1 寻道 |
| **A2** 主索引等值（键） | 聚簇 B+树，候选键 | **(h+1)(t_T + t_S)** |
| **A3** 主索引等值（非键） | 聚簇 | (h + b)(t_T+t_S) 附近 |
| ⭐ **A4** 二级索引等值（非键） | 非聚簇 | ⭐ **(h + n)(t_T + t_S)**，n = 匹配记录数（**每条一次随机 I/O**） |
| **A5/A6** 索引范围 | | 类似，叶子顺链走 |

### ⭐⭐ 外部排序（必考）
```
run 数 N = ⌈b_r / M⌉
每趟 fan-in = ⌊M / b_b⌋ − 1        （留 b_b 块做输出缓冲）
趟数 = ⌈log_(fan-in)(b_r / M)⌉
⭐ 总块传输 = b_r × (2 × 趟数 + 1)
```
**算例**：b_r=4000, M=40, b_b=4 → run 数=100；fan-in=⌊40/4⌋−1=**9**；趟数=⌈log₉100⌉=**3**；总传输=4000×(2×3+1)=**28,000**。

### ⭐⭐ Join 代价（必考）
| 算法 | 传输代价 | 寻道 | 限制 |
|:---|:---|:---|:---|
| **Nested-loop** | **n_r × b_s + b_r** | n_r + b_r | 任何条件 |
| ⭐ **Block nested-loop** | ⭐ **b_r × b_s + b_r** | **2 b_r** | 任何条件 |
| BNLJ + (M−2) 优化 | ⌈b_r/(M−2)⌉ × b_s + b_r | 2⌈b_r/(M−2)⌉ | |
| **一表全装入内存** | **b_r + b_s** | 2 | 最好情形 |
| **Indexed NL** | **b_r(t_T+t_S) + n_r × c** | | 内表要有索引；⭐ **两边都有索引时元组少的做外表** |
| **Merge join** | **b_r + b_s** | ⌈b_r/b_b⌉+⌈b_s/b_b⌉ | ⭐ **只适用等值/自然连接**；需已排序 |
| ⭐ **Hash join** | ⭐ **3(b_r + b_s)** | 2(⌈b_r/b_b⌉+⌈b_s/b_b⌉) | ⭐ **只适用等值/自然连接** |

**教材数字（要能复算）**：student n_r=5000, b_r=100；takes n_s=10000, b_s=400。
- NLJ（student 外表）= 5000×400 + 100 = **2,000,100**
- BNLJ = 100×400 + 100 = **40,100** 传输 + 200 寻道
- Indexed NL（takes 有 B+树，c=5）= 100 + 5000×5 = **25,100**
- Hash join（instructor 100 块 ⨝ teaches 400 块，M=20）= 3×(100+400) = **1500**

**Hash join 细节**：⭐ **build input = 较小的表**（每个分区必须装进内存，用**另一个**哈希函数建内存哈希索引）；probe = 大表。分区数 **n = ⌈b_s/M⌉ × 1.2**（fudge factor）。**倾斜/溢出** → 再分区或避免；重复键太多两者都失效 → 退化 BNLJ。⭐ **Hybrid hash join**：build 表的 0 号分区常驻内存，probe 表对应分区**直接现场探测不写盘**。

### ⭐ 物化 vs 流水线
| | **Materialization** | **Pipelining** |
|:---|:---|:---|
| 做法 | 中间结果**写盘** | 元组一产生就**直传父算子** |
| 适用性 | ⭐ **永远适用** | ⭐ **不总是适用**（阻塞算子） |
| 代价 | 各算子代价之和 + **中间结果读写盘** | ⭐ **省掉中间 I/O，更便宜** |
| 优化 | ⭐ **double buffering**（两输出缓冲交替，重叠计算与 I/O） | |

- **两种驱动**：⭐ **Demand-driven（lazy / pull，iterator: open/next/close）** ← BuzzDB 用的；**Producer-driven（eager / push，算子主动塞进缓冲区）**。
- ⭐ **阻塞算子**：**排序、（哈希）聚合、hash join 的 build** —— 消费完全部输入才出第一条结果。但可拆成子阶段参与流水线（sort = run 生成 + 归并；hash join = 分区 + build-probe）。

## C.8 ⭐⭐ ch18 并发控制

| 主题 | 必背要点 |
|:---|:---|
| **2PL** | 增长阶段只加锁、收缩阶段只放锁。⭐ **2PL 保证可串行化但防不了死锁**；**strict 2PL** = 写锁持到提交（防级联回滚）；**rigorous 2PL** = 所有锁持到提交 |
| **死锁** | 预防：⭐ **wait-die（老的等、少的死）**、**wound-wait（老的伤、少的等）**；⭐ **重启用原时间戳**（防饿死）。检测：**等待图有环**。 |
| **多粒度锁** | 意向锁 **IS / IX / SIX**；⭐ **加锁自顶向下，放锁自底向上** |
| **幻读** | ⭐ **`SELECT ... FOR UPDATE` 防不了幻读**（锁不住不存在的行）；用 **next-key locking / 谓词锁** |
| **TSO（时间戳排序）** | ⭐ **无死锁但可能饿死 + 级联回滚**；**Thomas 写规则：只忽略过时的【写】** |
| **OCC（验证协议）** | 读→验证→写三阶段；适合低冲突 |
| **MVCC / SI** | ⭐ **SI 有 write skew，不可串行化**；⭐ **Oracle 的 "serializable" 实为 SI** |
| **索引并发** | ⭐ **crabbing（螃蟹式加锁）可能死锁 → 用重启查找解决**；B-link tree 的 side pointer 让分裂可分两步 |

# 🧮 Part D · 计算题弹药库（期末 ~40% 的题在这里）

> **每条给三样：模板 → 算例 → 半步错误诱饵。**

## D-1 ⭐⭐⭐ B+ 树层数
```
扇出 f = 最大孩子数 × 填充率
层数 = ⌈log_f N⌉          【向上取整！】
校验法：f^h ≥ N 的最小 h
```
**算例（Final Practice Q2）**：N=12,000，最大孩子 100，75% 满 → f=75。
`75¹=75 < 12000`；`75²=5,625 < 12000`；`75³=421,875 ≥ 12000` → **3 层**。
自底向上验：12000/75=160 叶 → 160/75=2.13→3 个内部节点 → 1 个根 = **3 层** ✓
**诱饵**：⚠️ **向下取整得 2**（`log₇₅12000=2.18`）；⚠️ 忘乘填充率用 f=100。

## D-2 ⭐⭐⭐ B+ 树键数 / 叶子数计数
```
内部节点：键数 = 孩子数 − 1
叶子总数 = 最底层内部节点的孩子数之和
叶 payload 总数 = 叶子数 × 每叶记录数
```
**算例（Sheet 02 例题 3）**：高度 3，根有 4 个孩子；4 个内部节点分别有 3、5、4、2 个孩子；每叶恰好 3 条记录。
- 根的键 = 4−1 = **3**
- 内部节点的键 = (3−1)+(5−1)+(4−1)+(2−1) = 2+4+3+1 = **10**
- 内部分隔键合计 = 3+10 = **13**
- 叶子数 = 3+5+4+2 = **14** → payload = 14×3 = **42**
- **答案 (13, 42)**
**诱饵**：⚠️ **(12,45)** —— 12 来自"孩子数=键数"漏算；45 来自叶子数误算成 15。

## D-3 ⭐⭐⭐ 哈希探测走位
```
线性：  (h(k) + i) mod m
二次：  (h(k) + c₁i + c₂i²) mod m
双重：  (h₁(k) + i·h₂(k)) mod m      i = 0,1,2,…
```
**算例（Final Practice Q3）**：m=11，h₁=k mod 11，h₂=1+(k mod 5)，占用 {0,5,8}，插 k=27。
`h₁(27)=5`，`h₂(27)=1+2=3` → 探测 **5(X) → 8(X) → 0(X) → 3(空)** ⇒ **插在 3**。
**诱饵**：⚠️ **退化成线性探测**（5→6）；⚠️ 从最后一个占用槽 +1（8→9）；⚠️ h₂ 忘了 +1。

## D-4 ⭐⭐ Patricia Trie 插入增量
```
情形①  完全走完已有边、只标 terminal   → Δ节点 0，Δ字符 0
情形②  分裂一条已有边                  → Δ节点 +1，Δ字符 0 ⭐（分裂不增加字符总量）
情形③  新建分支（无公共前缀）           → Δ节点 +1，Δ字符 + 剩余后缀长度
```
**算例（Sheet 02 例题 5）**：已有 {he, hell, hello, helium, hero}，插入 {heli, help}。
- `heli`：走 `he`→`l`，剩 `i` 与子边 `ium` 的公共前缀是 `i`（比 `ium` 短）→ **分裂**：`ium` 拆成 `i`(terminal) + 子节点 `um`。Δ节点 **+1**，Δ字符 = (1+2)−3 = **0**
- `help`：剩 `p` 与任何子边无公共前缀 → **新建分支** `p`。Δ节点 **+1**，Δ字符 **+1**
- **合计 (2, 1)**
**诱饵**：⚠️ 以为分裂也增加字符 → (2,0) 或 (3,1)。

## D-5 ⭐⭐⭐ 外部排序
```
run 数 N = ⌈b_r / M⌉
fan-in   = ⌊M / b_b⌋ − 1
趟数     = ⌈log_(fan-in) (b_r / M)⌉
⭐ 总块传输 = b_r × (2 × 趟数 + 1)
```
**算例**：b_r=4000, M=40, b_b=4 → run 数=100；fan-in=⌊40/4⌋−1=**9**；趟数=⌈log₉100⌉=**3**；总传输=4000×7=**28,000**。
**诱饵**：⚠️ **fan-in 忘了 −1**（得 10 → 趟数 2）；⚠️ **总传输公式漏掉 "+1"**（写成 2×趟数）。

## D-6 ⭐⭐⭐ Join 代价
```
NLJ   = n_r × b_s + b_r
BNLJ  = b_r × b_s + b_r          （寻道 2b_r）
一表入内存 = b_r + b_s
Indexed NL = b_r(t_T+t_S) + n_r × c
Merge join = b_r + b_s           （需已排序，等值）
Hash join  = 3(b_r + b_s)        （等值）
```
**算例**：student n_r=5000, b_r=100；takes n_s=10000, b_s=400。
- NLJ = 5000×400+100 = **2,000,100**
- BNLJ = 100×400+100 = **40,100**
- Indexed NL（c=5）= 100 + 5000×5 = **25,100**
- Hash join = 3×(100+400) = **1,500**
**诱饵**：⚠️ **NLJ 用 b_r×b_s（那是 BNLJ）**；⚠️ **hash join 忘了系数 3**；⚠️ 外表/内表搞反。

## D-7 ⭐⭐ 选择算法代价
```
A1 线性扫描        = b_r 传输 + 1 寻道
A2 主索引等值(键)   = (h+1)(t_T + t_S)
⭐ A4 二级索引等值(非键) = (h + n)(t_T + t_S)     n = 匹配记录数
```
**算例**：h=3，匹配 20 条，t_T=0.1ms、t_S=4ms → A4 = (3+20)×4.1 = **94.3 ms**。
**诱饵**：⚠️ **A4 忘了 n**（写成 (h+1)）—— 非聚簇二级索引**每条匹配记录一次随机 I/O**，这是最常考的点。

## D-8 ⭐⭐ IOPS / 延迟比
```
IOPS = 1 / 单次 I/O 延迟（单请求未流水线时）
比值 = 慢的延迟 / 快的延迟
```
**算例（S1-Q23）**：HDD 8 ms vs SSD 80 μs → 8ms/80μs = 8000/80 = **100×**。
**诱饵**：⚠️ 单位没统一（ms vs μs）→ 得 10× 或 1000×。

## D-9 ⭐ 性价比 $/Mops
```
吞吐 ∝ 1/延迟；Mops = 10⁶ / 延迟(ns) … 统一后取比
$/Mops = 月成本 / 吞吐(Mops)      【越低越好】
```
**算例（S1-Q32）**：A：100 ns、$1000/月 → 吞吐 = 1/100ns = 10 Mops → **$100/Mops**。B：400 ns、$300/月 → 吞吐 = 2.5 Mops → **$120/Mops**。⇒ **A 更好，约 $100/Mops**。
**诱饵**：⚠️ 只比绝对价格选 B。

## D-10 ⭐ 槽页 / 页布局
```
每页记录数 = ⌊(页大小 − 页头) / (记录大小 + 槽项大小)⌋
平均扫描代价 = (记录数 / 2) × 每记录扫描成本      ⭐ 别忘 ÷2
```
**算例（S1-Q30）**：页均 64 元组；无槽扫描 0.05 μs/元组 → 平均 = 32×0.05 = **1.6 μs**；有槽 = **0.20 μs** 常数 ⇒ **有槽更快**。
**诱饵**：⚠️ **忘了 ÷2**（算成 64×0.05=3.2）；⚠️ 以为"要知道元组大小才能比"。

## D-11 ⭐⭐⭐ 列存 vs 行存页数
```
每页容纳值数 = 页大小 / 每值字节数
行存页数 = 行数 × 【总列数】/ 每页值数
列存页数 = 行数 × 【需要的列数】/ 每页值数
⭐ 比值 = 总列数 / 需要的列数
```
**算例**：800 万行 × 5 列，每值 8 B，4 KB 页，查询要 2 列。
每页 = 4096/8 = **512** 值；行存 = 8M×5/512 = **78,125** 页；列存 = 8M×2/512 = **31,250** 页；比值 = **2.5×**。
**诱饵**：⚠️ 列存那侧也按 5 列算；⚠️ 比值写成"总列数/1"。
⚠️ **别拿这个公式去套课程 weather 例子的 7 vs 4 页**——那组数字来自幻灯片具体的页分配图（每页装记录 1–40 的某一列），带了记录分块的粒度效应。

## D-12 ⭐⭐⭐ 压缩：位宽与压缩比
```
⭐ 先 shift（减最小值）再算位宽！
取值个数 R = max − min + 1
位宽 w = ⌈log₂ R⌉
压缩比 = 原位宽 / w
Delta encoding 后同理，对 delta 的范围算位宽
```
**算例 A**：温度 35–50 整数，原 4 字节。shift 后范围 0–15 → R=16 → **w = 4 bit** → 压缩比 = 32/4 = **8×**。
**算例 B（不 shift）**：温度 35/40/45/50 直接落在 0–63 → **w = 6 bit** → 压缩比 32/6 ≈ **5.3×**。
**诱饵**：⚠️ **漏掉 shift 这一步**（得 6 bit 而非 4 bit）—— 课程 transcript 里两个例子都有，极易混。

## D-13 ⭐⭐⭐ 执行模型加速比（Volcano / 向量化 / 编译）
```
每元组总成本_Volcano  = 控制开销 + 计算开销
每元组总成本_向量化   = 控制开销/批大小 + 计算开销
加速比 = 前者 / 后者
⭐⭐ 理论上限 = 总成本 / 计算开销     （批 →∞ 时控制开销 →0）
```
**算例（Final Practice Q6）**：Volcano 80+20=100 ns；向量化 200/1000+20=20.2 ns。
加速比 = 100/20.2 = **4.95 ≈ 5×**；**上限 = 100/20 = 5×**。
**诱饵**：⚠️ **只比控制开销**（80 vs 0.2 = 400×）；⚠️ 以为**加速比无上限**。
> ⭐ **这条是全卷最"跨材料"的公式**：向量化摊薄"解释开销"（P11），编译进一步优化"真正的计算"（P10），所以编译还能再快 2–4 倍。

## D-14 ⭐⭐ SIMD 指令数
```
向量宽度 W = 寄存器位宽 / 元素位宽
指令数 = N / W
削减倍数 = W
```
**算例**：400 万个 32 位整数，128 位寄存器 → W = 128/32 = **4** → 指令数 = 4,000,000/4 = **1,000,000**，削减 **4×**。
**常用 W 速查**：128 bit（NEON/SSE，`Q`）÷32 = 4；÷16 = 8；256 bit（AVX2）÷32 = 8；512 bit（AVX-512）÷32 = **16**。
**诱饵**：⚠️ 用错寄存器位宽；⚠️ 元素位宽看错。

## D-15 ⭐ 位图索引大小
```
一张位图大小 = 记录数 / 8 字节
位图 : 关系 的比 = 1 / (8 × 记录字节数)
AND 指令数 = 位数 / 64      （64 位字）
```
**算例**：记录 100 B → 一张位图 = 关系的 **1/800**；100 万条记录做 AND → 1,000,000/64 ≈ **15,625** 条指令。
**诱饵**：⚠️ 忘了除以 8（bit vs byte）。

## D-16 ⭐ 学习索引线性回归
```
slope = Σ(x−x̄)(y−ȳ) / Σ(x−x̄)²
intercept = ȳ − slope·x̄
预测位置 = ⌊slope·key + intercept⌋，再在 [pos−min_err, pos+max_err] 内局部搜索
```
**诱饵**：⚠️ 分母写成 Σ(y−ȳ)²；⚠️ 忘了最后要局部搜索。

## D-17 ⭐ 缓冲命中率 / 有效访问时间
```
有效访问时间 = 命中率 × 内存延迟 + (1 − 命中率) × 磁盘延迟
```
**算例**：命中率 95%，内存 100 ns，SSD 100 μs → 0.95×0.1μs + 0.05×100μs = 0.095 + 5 = **≈5.1 μs**。
**诱饵**：⚠️ 单位不统一；⚠️ 以为命中率 95% 就"几乎等于内存速度"（**miss 主导总时间**——这是很好的出题点）。

## D-18 ⭐ 封装影响的模块数
**算例（S1-Q26）**：`PAGE_SIZE` 被 5 个模块引用。**封装（私有于 StorageManager）→ 只改 1 个模块**；**不封装（全局）→ 5 个都要改**。

# ⚠️ Part F · 易错点 Top 40（考前最后 20 分钟扫这个）

## F.1 关系模型 / SQL（你的最大失血区）
1. ⭐ `π_X(π_Y(R)) = π_{X∩Y}(R)`，是**交集不是并集**，且需 **X ⊆ Y**；**投影不可交换**。
2. ⭐ **σ 才是"合并成 ∧"**：`σ_p(σ_q(R)) = σ_{p∧q}(R)`，且**可交换**。
3. ⭐ **集合语义下投影要去重 → 投影掉候选键会压缩元组 → 键不被投影保持**。
4. ⭐ **closure = 算子输出仍是关系**（不是"防止连接丢信息"）。
5. ⭐ **求值顺序 GROUP BY → HAVING → ORDER BY**；WHERE 过滤行、HAVING 过滤组。
6. ⭐ **无 ORDER BY 则顺序不保证**（关系是无序集合）。
7. **多对多关系表必须用复合主键**（两列各自是外键）。
8. **逗号分隔多值列违反 1NF**，后果是**查询变低效**（不是"简化检索"）。

## F.2 存储 / 硬件
9. ⭐ **DRAM 易失是因为电容漏电需刷新**；**NAND flash 是非易失的浮栅晶体管**。
10. ⭐ **页 < 块 → 读放大 + 写放大（read-modify-write）**，不是"减少碎片"。
11. **flash 写前需擦除 → 随机写慢于顺序写**。
12. ⭐ **PostgreSQL 默认 buffer 小是为了低内存机器能跑**，不是"小缓冲更高效"。
13. **SSD 上缓冲池大小配置**仍然关键；顺序预取变得不那么关键。
14. ⭐ **槽目录不保证元组能原地增长**（变大要搬走）。
15. **元数据写在页尾且无头指针 → 读者必须 seek 到末尾才知元组数**。
16. **内存改动只有写回/刷出后才持久**；⭐ **不是每次删除都要立刻 fsync**。

## F.3 C++ / BuzzDB
17. ⭐ **传/移动 unique_ptr 不会序列化它指向的数据**；必须写值并重建缓冲区。
18. ⭐ **序列化时内存指针必须换成文件偏移**；写指针值跨运行无意义。
19. ⭐ **深拷贝不共享缓冲区**（"共享以省内存"是反的）。
20. ⭐ **纯虚 `= 0` ≠ 编译期绑定**；虚函数走**运行期 vtable**；**模板是编译期实例化**。
21. **策略多态可在编译期和运行期都替换**。
22. ⭐ **`std::stoi` 不会拒绝 "100abc"**；`from_chars` 不抛异常不分配、返回首个未解析字符指针。
23. ⭐ **`reinterpret_cast` 不是"只要大小匹配就可移植且安全"**。
24. ⭐ **`mid = l + (h-l)/2`**，`(l+h)/2` 有整数溢出。
25. `lower_bound` = 第一个 **≥**；`upper_bound` = 第一个 **>**。
26. **RAII：异常时栈展开自动析构，不需要 delete[]**。

## F.4 索引
27. ⭐ **B+树精确查找必须到叶子**（"键等于内部分隔键可提前终止"是 **B-tree**）。
28. ⭐ **内部节点键数 = 孩子数 − 1**；计数题先算孩子。
29. **叶子分裂复制分隔键上去；内部分裂搬移中位键上去**；根分裂 → **所有路径同时加高**。
30. **删除借用后父分隔键要更新**；根只剩 1 孩子 → 删根、高度 −1。
31. ⭐ **二级索引必须稠密**；复合索引 (a,b) **a 范围 + b 等值不高效**。
32. ⭐ **哈希索引不支持范围查询是因为键无序**，不是哈希函数慢。
33. ⭐ **LSM 删除 = 插入 tombstone；查询要查多棵树**（Bloom filter 缓解）。
34. ⭐ **Patricia 分裂不增加字符总数**；trie 复杂度 **O(L) 与 N 无关**。
35. ⭐ **R-tree 无全序、无中序遍历**；**MBR 允许重叠**；**过空节点是 re-insert 不是合并**；**ChooseLeaf 首选面积增量最小**。
36. ⭐ **倒排索引生产主流是 document-partitioned**。
37. ⭐ **学习索引：阶段间无搜索；同阶段模型不必等大；不要求键均匀分布**。

## F.5 执行 / 列存 / 并发
38. ⭐ **HashAggregation 是阻塞算子且输出无序** → ORDER BY 要加 Sort（分组键=排序键时可换有序聚合）。
39. ⭐ **向量化只摊薄控制开销，计算开销不变 → 加速比有硬上限 = 总成本/计算成本**。
40. ⭐ **压缩比最高 ≠ 查询最快**（Huffman 2.24 ms 慢于 byte dictionary 0.71 ms，因为**解码成本**）。
41. ⭐ **列存 30× 的前提是 highly selective filter**。
42. ⭐ **查询编译的两个缺点：编译耗时（短查询反而更慢）+ 灵活性差（schema 变要重编译）**。
43. ⭐ **2PL 防不了死锁**；**SI 有 write skew 不可串行化**；**`SELECT FOR UPDATE` 防不了幻读**。
44. ⭐ **hash join 只适用等值/自然连接**；**build input 是较小的表**；**输入已排序时 merge join 更优**。
45. ⭐ **A4 二级索引等值（非键）代价 = (h + n)(t_T+t_S)**，别漏 n。
46. ⭐ **外部排序 fan-in = ⌊M/b_b⌋ − 1**（别漏 −1）；**总传输 = b_r(2·趟数 + 1)**（别漏 +1）。
