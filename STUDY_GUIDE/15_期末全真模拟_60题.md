# ✅ 答案与详解

## Part I · 计算题

**1. B（3 层）**
```
f = 200 × 0.6 = 120
120¹ = 120        < 500,000
120² = 14,400     < 500,000
120³ = 1,728,000  ≥ 500,000  → 3 层
```
⚠️ **诱饵 A=2**：`log₁₂₀500000 = 2.74` **向下取整**。索引层数永远**向上取整**。

**2. B（4 层）**
```
f = 400 × 0.75 = 300
300³ = 27,000,000   < 100,000,000
300⁴ = 8.1 × 10⁹    ≥ 100,000,000  → 4 层
```
⚠️ **诱饵 A=3**：只算到 300³ 就停手。

**3. B（1022）**
```
8m + 13 ≤ 8192  →  8m ≤ 8179  →  m ≤ 1022.375  →  m = 1022
```
⚠️ **A=510** 是 4 KB 页的答案；**D=2046** 是 16 KB 页的答案。**三个页大小的值都要记：4KB→510、8KB→1022、16KB→2046。**

**4. A（19, 80）**
```
根的键        = 5 − 1 = 4
内部节点的键  = (4−1)+(3−1)+(6−1)+(2−1)+(5−1) = 3+2+5+1+4 = 15
内部分隔键合计 = 4 + 15 = 19
叶子数        = 4+3+6+2+5 = 20
叶 payload    = 20 × 4 = 80
```
⚠️ **诱饵 B=(20,80)**：把根的孩子数 5 当成键数。⭐ **内部节点键数 = 孩子数 − 1**，计数题先算孩子。

**5. B**
n=5 → 叶子最多 4 个值。装满后再插第 5 个 → 分裂成 **⌈5/2⌉ = 3** 和 **2**。
⭐ **叶子分裂是"复制"分隔键上去**（右叶的最小键被**复制**到父节点，叶子里仍保留它）；**内部节点分裂才是"搬移"中位键**（本节点不再保留）。
⚠️ C 把"复制"说成"搬移"，且叶子会丢值——错。A 说丢弃一个值——B+树不丢数据。

**6. D（Index 12）**
```
h₁(43) = 43 mod 13 = 4        (43 = 3×13 + 4)
h₂(43) = 1 + (43 mod 7) = 1 + 1 = 2   (43 = 6×7 + 1)
探测 (4 + 2i) mod 13：
 i=0 → 4   (X)
 i=1 → 6   (X)
 i=2 → 8   (X)
 i=3 → 10  (X)
 i=4 → 12  (空) ✓
```
⚠️ **诱饵 A=5**：退化成线性探测（4→5）。**C=11**：从最后一个占用槽 10 线性 +1。

**7. A（Index 1）**
```
h(25) = 25 mod 11 = 3
探测 (3 + i²) mod 11：
 i=0 → 3        (X)
 i=1 → 3+1 = 4  (X)
 i=2 → 3+4 = 7  (X)
 i=3 → 3+9 = 12 mod 11 = 1  (空) ✓
```
⚠️ **诱饵 D=12**：忘了 mod 11。**B=5**：用了线性探测。

**8. C（2, 4）**
起始结构：`root -"ca"-> A`；`A -"r"-> B(term:car)`；`A -"t"-> C(term:cat)`；`B -"t"-> D(term:cart)`；`B -"e"-> E(term:care)`。
- **插 "carpet"**：走 `ca`→A，`r`→B（已消耗 "car"），剩 `pet`。B 的子边是 `t`、`e`，**与 `pet` 无公共前缀** → **新建分支** `pet`。Δ节点 **+1**，Δ字符 **+3**。
- **插 "cab"**：走 `ca`→A，剩 `b`。A 的子边是 `r`、`t`，**无公共前缀** → **新建分支** `b`。Δ节点 **+1**，Δ字符 **+1**。
- **合计 (2, 4)**。
⚠️ 本题两次都是**情形③新建分支**，没有分裂。

**9. B（2, 1）**
起始结构：`root -"test"-> B(term)`；`B -"ing"-> C(term)`。
- **插 "tea"**：从 root 出发，边标签 `test` 与 `tea` 的**公共前缀是 `te`（长度 2 < 4）→ 分裂**：`test` 拆成 `te` + 子边 `st`。**新增节点 1 个**；字符 (2+2) − 4 = **0**。
- 分裂后从新节点出发，`tea` 剩 `a`，无公共前缀 → **新建分支** `a`。**新增节点 1 个**，字符 **+1**。
- **合计 (2, 1)**。
⭐ **必背：分裂 → Δ节点 +1、Δ字符 0（分裂不增加字符总量）；新建分支 → Δ节点 +1、Δ字符 = 剩余后缀长度。**

**10. C（84,000）**
```
run 数   = ⌈12000 / 60⌉ = 200
fan-in   = ⌊60 / 6⌋ − 1 = 10 − 1 = 9
趟数     = ⌈log₉ 200⌉ = ⌈2.41⌉ = 3        (9² = 81 < 200 ≤ 729 = 9³)
总块传输 = 12000 × (2 × 3 + 1) = 12000 × 7 = 84,000
```
⚠️ **诱饵 B=72,000**：公式**漏掉 "+1"**（写成 2×趟数）。**A=60,000**：趟数算成 2。

**11. C（160,200）**
```
BNLJ = b_r × b_s + b_r = 200 × 800 + 200 = 160,200
```
⚠️ **诱饵 D=6,400,200** 是 **NLJ**（`n_r × b_s + b_r` = 8000×800+200）——⭐ **NLJ 用元组数，BNLJ 用块数**，这是最常考的混淆点。**A=1,000** 是"一表全装入内存"的最好情形。

**12. B（Hash join；3,000）**
```
Hash join           = 3 × (200 + 800) = 3,000          ✓ 最低
BNLJ + (M−2) 优化   = ⌈200/23⌉ × 800 + 200 = 9×800+200 = 7,400
Merge join          = 需要先排序，题目说未排序 → 要加排序代价，不能直接算 1,000
Indexed NL          = 题目说没有索引 → 不可用
```
⭐ **关键判断链：等值连接 + 无序 + 无索引 → hash join；已排序 → merge join；非等值 → 只能 (B)NLJ。**

**13. C（72,300）**
```
Indexed NL = b_r + n_r × c = 300 + 12,000 × 6 = 300 + 72,000 = 72,300
```
⚠️ **诱饵 A=12,300**：漏掉了 c（写成 300 + 12000）。**B=13,800**：把 c 乘到了 b_r 上。

**14. D（139.4 ms）**
```
A4（二级非聚簇索引、非键等值）代价 = (h + n)(t_T + t_S)
                                   = (4 + 30) × (0.1 + 4) = 34 × 4.1 = 139.4 ms
```
⚠️ **诱饵 B=20.5**：用了 (h+1)×4.1，**漏掉 n**。⭐ **非聚簇二级索引每条匹配记录都要一次随机 I/O**，这是最高频的失分点。

**15. A（62,500 vs 15,625；4×）**
```
每页容纳值数 = 8192 / 4 = 2048
行存 = 16,000,000 × 8 / 2048 = 128,000,000 / 2048 = 62,500 页
列存 = 16,000,000 × 2 / 2048 =  32,000,000 / 2048 = 15,625 页
比值 = 8 / 2 = 4×
```
⭐ **通用结论：纯列存全扫的页数比 = 总列数 / 需要的列数**（无压缩、定长、每列独立成页时）。

**16. A（6 bits；≈5.3×）**
```
取值个数 R = 1263 − 1200 + 1 = 64
位宽 w = ⌈log₂ 64⌉ = 6 bits
压缩比 = 32 / 6 ≈ 5.3×
```
⚠️ **诱饵 B=11 bits**：**没做 shift**，直接对 1263 算 ⌈log₂1264⌉ = 11。⭐ **先减最小值再算位宽**——这一步是课程 temperature 列的标准做法。

**17. B（4 bits）**
```
delta 范围 1..16  →  shift 后 0..15  →  16 个取值  →  w = ⌈log₂16⌉ = 4 bits
```
⚠️ **诱饵 C=5 bits**：**不 shift** 直接存 1..16，16 = 二进制 10000 需要 5 位。⭐ **题干明确说了"additionally shifted by their minimum"，这一步就是本题的全部考点。**

**18. A（≈5×；上限 5×）**
```
Volcano  = 100 + 25 = 125 ns/元组
向量化   = 400/2000 + 25 = 0.2 + 25 = 25.2 ns/元组
加速比   = 125 / 25.2 ≈ 4.96 ≈ 5×
⭐ 上限  = 125 / 25 = 5×      （批 →∞ 时控制开销 →0，只剩计算开销）
```
⚠️ **诱饵 B（无上限）**：⭐ **谓词求值的 25 ns/元组一分不减**，所以加速比有硬上限。**C=125×**：只比了控制开销。

**19. C（解释更好：900 ms vs 2,030 ms）**
```
编译后执行 = 900 / 30 = 30 ms
编译 + 执行 = 2000 + 30 = 2,030 ms  >  900 ms
```
⭐ **这就是 module_11 明确列出的第一个缺点**：*"If the execution time of the query is short, then the **total time to compile and run it might actually be longer than just interpreting it**."*
💡 若同一查询要跑 N 次：`2000 + 30N < 900N` → `N > 2.26` → **跑 3 次以上编译才划算**。

**20. A（1,500,000；16×）**
```
向量宽度 W = 256 bit / 16 bit = 16
指令数 = 24,000,000 / 16 = 1,500,000
削减倍数 = 16×
```
⭐ **常用 W 速查**：128 bit（NEON/SSE，`q`）÷32 = 4；256 bit（AVX2）÷32 = 8、÷16 = **16**；512 bit（AVX-512）÷32 = 16。

**21. A（500 KB；1/1600）**
```
一张位图 = 4,000,000 bit / 8 = 500,000 字节 = 500 KB
关系大小 = 4,000,000 × 200 B = 800,000,000 字节 = 800 MB
比值 = 500,000 / 800,000,000 = 1/1600
公式校验：1 / (8 × 记录字节数) = 1/(8 × 200) = 1/1600 ✓
```
⚠️ **诱饵 B=4 MB**：忘了除以 8（把 bit 当 byte）。

**22. B（≈500×）**
```
10 ms / 20 µs = 10,000 µs / 20 µs = 500
```
⚠️ **单位必须先统一**。（课程原例是 8 ms vs 80 µs = 100×。）

**23. C（≈10.1 µs）**
```
= 0.9 × 0.1 µs + 0.1 × 100 µs = 0.09 + 10 = 10.09 ≈ 10.1 µs
```
⭐ **反直觉点（很好的出题素材）**：命中率高达 90%，有效时间仍被 **miss 主导**（10 µs 中 miss 贡献了 10 µs）。
💡 要让有效时间 < 1 µs，需要 `(1−h)×100 + h×0.1 < 1` → **h > 99.1%**。

**24. A（78）**
```
可用空间 = 8192 − 24 = 8168 字节
每条记录占用 = 100（记录）+ 4（槽项）= 104 字节
记录数 = ⌊8168 / 104⌋ = ⌊78.5⌋ = 78
```
⚠️ **诱饵 B=80**：忘了减页头或忘了算槽项。⭐ **槽页计算一定要把"槽目录项"算进每条记录的开销。**

## Part II · 跨论文归属题

**25. D。** 查询编译成机器码、把算子融进紧循环是 **P10 HyPer (Neumann)** 和 `module_11` 的技术。**C-Store（2005）是解释执行**——10 种算子 + 64K 单列块迭代器，没有代码生成。A/B/C 都是 C-Store 归因里的原话。

**26. B。** **PDT（Positional Delta Trees）按位置而非键值组织差分**是 Vectorwise 的。A（K-safety + 多 sort order）、C（HWM/LWM/epoch/IV/DRV 快照隔离）、D（Type 2 位图编码）**全是 C-Store**。
⭐ **关键辨析：Vectorwise 只存一份数据副本，因此每表只能有一个 clustered index，不可能提供"多种 sort order 任选"，也没有 K-safety。**

**27. B。** exchange 是 **Volcano (P9)** 的，⭐ **它本身就是一个 iterator**，封装 **vertical / bushy / intra-operator** 三种并行。
- A 错：P8 的对应机制叫 **split & merge 算子**，speedup/scaleup 是 P8 的定义但与 exchange 无关。
- C 错：P10 的 push 模型不叫 exchange。
- D 错：C-Store 的 WS→RS 迁移叫 **tuple mover / MOP**。

**28. A。** mapping table + delta + CAS = **Bw-Tree (P5)**；最容易与 **Umbra (P4)** 混——Umbra 用的是 **swip（指针混写）+ 版本化闩锁（独占/共享/乐观）+ 可变大小页**。

**29. D。** "把所有并行性封装进一个**既使用又提供标准 iterator 接口**的算子"是 **Volcano (P9)** 的 operator model 主张。A、B、C 都是 P8 的。

**30. B。** `position = F(key) × N` 是 **Learned Index (P7)** 的核心等式，直接对标替换 **B-Tree 范围索引**（论文的第 2 节标题就是 RANGE INDEX）。

## Part III · 概念反选题

**31. D。** 恰恰相反——课程演示的是**不同列用不同算法**：timestamp 用 delta、temperature 用 shift+bit packing、product ID 用 byte dictionary/Huffman，且方案与参数是**自动逐列选择**的。（手法①绝对化 + ②方向反转）

**32. D。** ⭐ **Byte dictionary 只在"唯一值数量有限"时有用**（要映射到 0–255 的单字节码），**百万级不同值会直接爆掉**；而且它面向 **categorical** 数据，不是 numeric。（手法⑤张冠李戴）

**33. D。** ⭐ **压缩比最高 ≠ 查询最快**：Huffman 压缩比更高却比 byte dictionary **慢 3 倍**（2.24 ms vs 0.71 ms），因为**按位解码的开销**才是查询时的瓶颈。（手法①绝对化 + 与实测数据矛盾）

**34. D。** 原文：*"Finally, we handle any **leftover elements if our total count isn't a multiple of four in a scalar loop**… Combining the vectorized portion with a simple **scalar tail case is a common pattern for SIMD algorithms**."*（手法①绝对化）

**35. C。** 方向反转——**行存最擅长访问完整的行，列存最擅长访问特定的列**。列存要拼回完整行反而要付 **tuple reconstruction** 的代价。

**36. D。** ⭐ **正则只在 parse 阶段跑一次**，与 tuple 数量无关。真正的第四个开销是 **memory 开销：算子里频繁创建/销毁临时对象（如指向 field 的 unique_ptr）**。（手法④不存在的机制）

**37. D。** 原文明确反驳：*"**If the execution time of the query is short, then the total time to compile and run it might actually be longer than just interpreting it.**"* 另一缺点是 schema 变了要重编译。（手法①绝对化 `regardless of`）

**38. C。** ⭐ **HashAggregation 的输出顺序由哈希函数决定，与键的大小顺序无关 → planner 绝不能假设其输出有序。** 这是 Sheet 02 例题 4 的原答案。

**39. D。** ⭐ **B+树精确查找必须走到叶子**，因为 **payload 只在叶子**；"键等于内部分隔键可提前终止"是 **B-tree** 的性质。这是 Sheet 02 例题 1 的原答案。（手法⑤张冠李戴）

**40. D。** ⭐ **R-tree 用的是 re-insertion（消除过空节点 + 把项重新插入），不是与兄弟合并。** Guttman 给的两个理由：① 复用 Insert 例程更易实现、需要的页通常已在内存；② **再插入会渐进精炼树的空间结构，防止逐渐劣化**。

**41. C。** ⭐ **同一阶段的模型不必覆盖等大的键范围**——键空间按上层模型的**预测**划分，随数据分布自适应。这是"特性不是缺陷"。（手法⑤把 B-tree 的性质安给 RMI）

**42. A。** ⭐ **间接引用的用途是"同一元组内两列比较"和动态条件，不是"在索引查找中大量使用并被高度优化"**（索引查找用的是键值/常量，那是 direct reference）。Sheet 02 例题 7 原答案。

**43. D。** ⭐ **hash join 对倾斜并不免疫**：某分区装不下内存（同键值太多或哈希不均）会**溢出**，需要**再分区（resolution）或避免（avoidance）**；**重复键太多时两者都失效，只能退化用 BNLJ**。（手法⑥半真半假）

**44. D。** 方向反转——**"算子主动把元组推进缓冲区、缓冲满则阻塞"是 producer-driven（eager / push）**；**demand-driven 是 lazy / pull**，上层不断向下层要下一个元组（iterator: open/next/close，正是 BuzzDB 用的）。

**45. C。** ⭐ **快照隔离有 write skew，不可串行化**（Oracle 的 "serializable" 实为 SI）。A、B、D 都对。

**46. D。** ⭐ **LSM 的写放大恰恰来自反复归并（compaction）**，在**读多写少或随机更新**的负载下未必优于 B+树；"never rewrite data" 也不成立。（手法①绝对化 `under all workloads` + ②方向反转）

**47. B。** ⭐ **exchange 是唯一的例外**：*"While all other modules are based on **demand-driven dataflow**, the producer-consumer relationship of exchange uses **data-driven dataflow**."* 选 data-driven 的两个理由之一正是**消除请求消息的需要**——B 把因果关系接反了。

**48. C。** ⭐ **页分裂改变了三个页（原页 O、新兄弟 N、父页 P），无法用一次 CAS 装上**；Bw-tree 把 SMO 拆成**一串各自可用一次 CAS 装上的原子动作**，靠 **B-link 的 side pointer** 让 half split 之后索引就已经合法。

## Part IV · C++ / BuzzDB 代码题

**49. C。** ⭐ **纯虚 `= 0` 表示"必须被派生类实现"，与绑定时机无关**；通过基类指针调用**走运行期 vtable 分派**。这正是 `module_11` 列出的解释开销第 3 条。（手法③编译期/运行期偷换 —— Sheet 01 Q18 考过一模一样的坑）

**50. D。** ⭐ **`std::unique_ptr` 不可复制，只能移动**——一旦 `getOutput()` 把所有权移交出去，再次调用不可能"自动"再变出一份独立副本；要得到独立副本**必须显式写深拷贝逻辑**（`SelectOperator` 就是这么做的，见 C）。（手法④不存在的机制）

**51. D。** ⭐ **`(l+h)/2` 的整数溢出是真实 bug**（JDK 二分查找潜伏 9 年），而且**有符号整数溢出在 C++ 里是未定义行为**，编译器**不保证**回绕无害。正解是 `l + (h-l)/2`。

**52. D。** ⭐ **bit packing 是定宽的**——每个值恰好占 `width` 位，所以**元素 i 的起始位置 = i × width，可以直接算出来随机访问**（`extract_value` 正是这么做的，见 B）。**需要顺序重放才能访问的是 delta encoding**，不是 bit packing。（手法⑤张冠李戴：把 delta 的性质安给 bit packing）
> ⭐ 这正是 Final Practice Q1 选项 A 讲的事——**两种编码的随机访问性质完全不同，务必分清。**

**53. D。** ⭐ **正则只在 parse 阶段执行一次**，产出 `QueryComponents` struct；执行阶段用的是搭好的算子链，与正则无关。

**54. D。** ⭐ **SIMD 的关键技巧正是"用 mask 代替分支"**：把 mask 转成 float 向量后用 `vmulq` 与温度**逐元素相乘**（范围外变 0、范围内保留原值），再用 `vaddq` 累加——*"seamlessly integrates conditional filtering **without resorting to branch instructions**"*。（手法②方向反转）

## Part V · 短事实题

**55. B。** `std::map` = **红黑树**，O(log N)，**有序、支持范围查询**；`std::unordered_map` = **哈希表**，平均 O(1)，**无序、不支持高效范围查询**。

**56. B。** DRAM 每 bit 存在**电容**里，**电容漏电所以必须周期性刷新**（"Dynamic" 就指这个），断电即丢。**NAND flash 是非易失的浮栅晶体管**，是 SSD 的材料。

**57. C。** **Grouping → HAVING filtering → Ordering**。⭐ **HAVING 作用在"分组后的组"上，必须先分组**；ORDER BY 作用在最终结果集上，永远最后。

**58. C。** 硬件最小传输单位是**块**，读 1 KB 页要拉整个 4 KB 块 → **4× 读放大**；写更糟（read-modify-write → 写放大）。

**59. B。** **Closure = 关系算子的输入是关系、输出也是关系**，因此可任意嵌套组合。⚠️ A 讲的接近 lossless-join decomposition，C 讲的是 attribute closure X⁺——**closure 在本课有三种同名异义**。

**60. B。** **document-partitioned**：按文档切 shard、每 shard 建本地倒排索引、**查询广播给所有 shard 后由 coordinator 归并**。⭐ **transcript 教的是 term-partitioned 作为示例，但生产主流是 document-partitioned** —— 这是"超出 transcript 一小步"的典型考点。
