## 1. 为什么数据非要落盘：DRAM vs 磁盘

**📖 原文：** *"DRAM... is used for fast short-term data access... data stored in memory is lost if the power is interrupted. Persistent storage devices like solid state drive (SSD) and hard disk drive (HDD)... retain data even through power outages."*

**💡 大白话：** 就两种存储，各有各的脾气：

| | **DRAM（内存）** | **SSD/HDD（磁盘）** |
|:---|:---|:---|
| 断电 | **数据全没**（易失 volatile） | **数据还在**（持久 persistent） |
| 速度 | 快（≈ 50 纳秒 ns） | 慢（SSD ≈ 50 微秒 µs，**慢约 1000 倍**） |
| 价格 | 贵（≈ $10/GB） | 便宜（SSD ≈ $0.10/GB，**便宜约 100 倍**） |

矛盾就在这：内存快但断电就忘、磁盘慢但记得住。所以数据库的**全部功夫**就是——**怎么让又慢又笨的磁盘，用起来像又快又聪明的内存**。

**数据的两段旅程**（原文）：① 事务先改**内存**（快）；② commit 后把改动刷到**磁盘**（持久）。
> 🔵 类比：你写文档时改的是屏幕上的内容(内存)，按 Ctrl+S 才存到硬盘(磁盘)。没存就断电，改的就丢了。

**📝 考试这么考：**
- ✅ *"Caching frequently accessed pages in DRAM reduces slow disk I/O, but DRAM is volatile so data must eventually be persisted to disk."*
- ❌ *"DRAM is much cheaper than SSD, so all data should be kept in DRAM."* —— 错，DRAM **比 SSD 贵得多**。

## 2. 磁盘为什么慢 + IOPS（ch12 重点，常出计算题）

**📖 原文（ch12）：** *"Access time consists of: Seek time... Rotational latency... Data-transfer rate."*

**💡 大白话：** 机械硬盘(HDD)读一块数据要三步：
1. **寻道(seek)**：磁臂移到正确的"磁道"（4–10ms）。
2. **旋转延迟(rotational latency)**：等盘片转到磁头底下（4–11ms）。
3. **传输**：真正把数据读出来。
> 🔵 类比：在**老式黑胶唱片**上找某首歌——先移唱针到大概位置(寻道)，再等唱片转到那一段(旋转延迟)。所以**随机访问巨慢**(每次都要寻道+转)，**顺序访问快**(只寻道一次)。

**IOPS = 每秒能做多少次随机读。** HDD 只有 50–200，SSD 上万。
> 🔑 **考试公式**：**IOPS ∝ 1/延迟**。SSD vs HDD 的 IOPS 比 = HDD延迟 ÷ SSD延迟（注意 ms↔µs：1ms = 1000µs）。

**📝 考试这么考（计算题，测验 Q23）：**
- ✅ *"HDD ≈ 8 ms, SSD ≈ 80 µs per random read → SSD achieves ≈ 100× higher IOPS."* （8ms ÷ 80µs = 8000÷80 = 100）

## 3. ⭐⭐ 序列化 / 反序列化（核心中的核心，讲最透）

**📖 原文：** *"Serialization is the process by which we convert in-memory data into a format suitable for storage on disk. Conversely, deserialization involves reconstructing the in-memory data from the data stored on disk."*

**💡 大白话：**

先看**根本问题**：内存里的对象，**不能直接复印到磁盘**。为什么？

内存里的字符串 `"Alice"` **不是**规规矩矩排好的 5 个字母，它更像一张**便利贴**，上面写着："真字母在内存 **#48291 号柜子**里，长度 5"。字母本身在别处。而那个 `#48291` 地址**只在这次程序运行时有效**——你把 `48291` 写到磁盘，明天再开程序，#48291 号柜子里装的是完全不相干的东西。**地址存下来毫无意义。**

所以：
> **序列化 = 把内存里"带地址、东一块西一块"的数据，压扁成一长条「规规矩矩、自带内容、不含地址」的字节**，才能安全写磁盘。
> **反序列化 = 完全相反**：把磁盘字节读回来，在内存重新盖一个能用的对象。

`"Alice"` 序列化后写到磁盘：先写**长度 `5`**，再写 5 个真字母 `A l i c e`。**没有地址**，字母实实在在躺那。反序列化：读到 `5` → 接着读 5 个字节 → 在内存申请新地方拷进去 → 又有了能用的 `"Alice"`。

**两个生活类比（记一个就够）：**
| 类比 | 序列化 | 反序列化 |
|:---|:---|:---|
| 🎮 游戏存档/读档 | 点"存档"：把内存里活的角色/进度写成存档文件存硬盘 | 点"读档"：把存档文件读回内存重建角色 |
| 📦 宜家家具 | 组装好的书架没法寄→拆成平板+螺丝+说明书装箱 | 收货人开箱按说明书重新组装 |

**BuzzDB 具体怎么序列化一页**（原文）：*"...first writing out the total number of tuples... For each field, the field's type and data length are first recorded... The data length is important during deserialization for dynamically sized fields like strings."*

大白话：**先写"这页几个元组" → 每个元组写"几个字段" → 每个字段写 `[类型][长度][真数据]`**。那个 **`长度`** 关键——字符串长度不定，反序列化得先知道"这个字符串读 8 字节就停"，否则会读过头串到下一字段。

**📝 考试这么考（你错过的题）：**
- ✅ *"In memory a std::string uses pointers/capacity for dynamic growth; on disk it is linearized into a byte stream with a length, so raw pointers are neither stored nor meaningful."* （测验 Q7 正解）
- ❌ *"Moving a unique_ptr into a write function automatically serializes the pointed-to data."* —— 错（Q2）！传指针**不会**自动序列化，必须**手动写出值(长度+字节)**。
- ❌ *"Writing the tuple-count metadata after all tuple bytes makes deserialization faster."* —— 错（Q3）！元数据放末尾，读者得 seek/扫到末尾才知数量，**更复杂**。所以要放**头部**。

## 4. Page 类（页）

**📖 原文：** *"Pages serve as the basic unit of data storage on disk. Each disk page is typically 4 kilobytes in size. BuzzDB groups tuples together into these fixed size pages."*

**💡 大白话：** 磁盘不是一个字节一个字节读写的，而是**一页一页**(通常 4KB)读写。BuzzDB 把多个元组打包进一页，插入前先检查"加上这个元组会不会超过 4KB"。
> 🔵 类比：寄快递不是一件件塞，而是装进**标准纸箱**(页)，一箱箱发。每箱装满为止。

## 5. Field 类：让数据库能存多种类型（int/float/string）

**📖 原文：** *"The field class uses a union to allocate memory for either an integer or a float based on the type of the field. Unions allow different data types to share the same memory location."*

**💡 大白话：** 最初 BuzzDB 只能存整数。要支持小数、字符串，就造一个 `Field` 类，关键技术：
- **enum(枚举)**：`FieldType {INT, FLOAT, STRING}` —— 给类型起名字，代码好读。
- **union(联合体)**：让 int/float/字符串指针**共享同一块内存**(省空间，大小=最大的那个成员)。
  > 🔵 类比：一个**多功能插座**，同一个孔位，这次插 int、下次插 float——但同时只能插一种。
- **构造函数重载(constructor overloading)**：写好几个构造函数(一个收 int、一个收 float、一个收 string)，根据你传什么**自动选**。
- **字符串要动态内存**：字符串长度不定，得用 `new` 在**堆**上现申请空间（`长度+1`，那个 +1 是给结尾的 `\0` 终止符）。
- **析构函数(destructor)**：对象销毁时**自动**调用，负责 `delete` 释放堆内存。**每个 `new` 必须配一个 `delete`**。

**📝 考试这么考：**
- ✅ *"A union lets a Field hold an int, float, or string pointer in the same memory, sized to the largest member."*

## 6. ⭐ 裸指针四坑 → 智能指针 → RAII（必懂）

**📖 原文：** *"There are four important problems associated with raw pointers: memory leaks, dangling pointers, double free errors, and ownership ambiguity. Smart pointers like std::unique_ptr are designed to provide automatic memory management."*

**💡 大白话：** "裸指针"(自己 new/delete 管的指针)有四个大坑：

| 坑 | 啥意思 | 后果 | 🔵 类比 |
|:---|:---|:---|:---|
| **内存泄漏 memory leak** | new 了忘记 delete | 内存越用越多直到崩 | 借了书不还，书架越借越空 |
| **悬空指针 dangling pointer** | 内存已释放，指针还指着 | 一访问就崩/乱 | 朋友搬走了你还往老地址寄信 |
| **重复释放 double free** | 同块内存 delete 两次 | 未定义行为/崩 | 同一本书还两次，图书馆懵了 |
| **所有权不清** | 不知道谁该 delete | 多处共用时混乱 | 几个人合租，没人知道谁倒垃圾 |

**解药：`std::unique_ptr`（智能指针）**——它**离开作用域时自动 delete**，杜绝泄漏；**唯一所有权**(只能有一个主人)，杜绝重复释放；reset/转移时自动置空，不会悬空。

**RAII(资源获取即初始化)** = 把资源(内存/文件/锁)的命**绑到对象的命上**：对象一建就拿资源，对象一毁就放资源。智能指针、文件流、锁都是这个原理。
> 🔵 类比：**自动感应灯**——你进房间(对象建)灯自动亮(拿资源)，你走了(对象毁)灯自动灭(放资源)，不用记得手动关。

**📝 考试这么考（你错过的题）：**
- ✅ *"When an exception is thrown, stack unwinding destroys the unique_ptr and frees its memory automatically—no manual delete[] is needed."* （测验 Q6 正解）
- ❌ *"To avoid a leak, you must call delete[] in a catch block."* —— 错！RAII 自动释放。

## 7. 深拷贝 vs 浅拷贝（+ move）

**📖 原文：** *"The copy constructor for the field class ensures that when a new field object is created as a copy... it receives a new independent copy of the string. This is known as deep copying."*

**💡 大白话：**
- **深拷贝(deep copy)**：复制出**一份独立的**数据。两个对象各管各的，互不影响。
- **浅拷贝(shallow copy)**：只复制那张"便利贴"(指针)，两个对象**指向同一份**数据——危险！一个改了另一个跟着变，一个销毁另一个就悬空。
> 🔵 类比：深拷贝 = 把文件**打印一份**给同事(各有各的)；浅拷贝 = 把文件的**链接**发给同事(共享同一个，他删了你也没了)。

- **`unique_ptr` 不能拷贝**(唯一所有权)，但能 **move**(`std::move` 把所有权**转移**给别人，自己变空，无复制开销)。
> 🔵 类比：move 像**把房产证过户**给别人，不是复印一张——过户后你就不是房主了。

**📝 考试这么考（你错过的题）：**
- ✅ *"Deep copy gives each object an independent copy, so passing by value is safe and destroying one copy does not dangle others."*
- ❌ *"Deep copy minimizes memory by sharing common buffers among objects."* —— 错（Q4）！**共享缓冲**是**浅拷贝**；深拷贝恰恰**不共享**(更费内存、更安全)。

## 8. 堆 vs 栈（heap vs stack）

**📖 原文：** *"Heap allocated variables have a lifespan that extends beyond the scope... Stack allocated variables are only alive during the block scope in which they are defined."*

**💡 大白话：**

| | **堆 Heap** | **栈 Stack** |
|:---|:---|:---|
| 谁管 | 你/智能指针(用 `new`) | C++ 自动 |
| 活多久 | 到你显式释放(超出作用域还在) | **函数一返回就销毁** |
| 大小 | 大 | 小 |
| 速度 | 慢(有碎片管理) | 快 |

> 🔵 类比：栈 = 你办公桌上的便签，下班(函数返回)就被清掉；堆 = 仓库里的货，你不主动搬走它就一直在。

> ⚠️ **大坑**：函数返回一个**栈上对象**的引用/指针 → 那对象函数一返回就没了 → 指针**悬空** → 未定义行为。要持久就放**堆**(配智能指针)。

## 9. reinterpret_cast（读磁盘原始字节时用）

**📖 原文：** *"reinterpret_cast... is akin to reinterpreting the raw binary data of one type as another... powerful and must be used carefully."*

**💡 大白话：** 把一种指针**强行当成另一种**来读(如把一串原始字节 `char*` 当成"槽数组 `Slot*`")。它**不改二进制值，只改你怎么解读这堆字节**。底层读写磁盘字节时要用，但很危险。
> 🔵 类比：同一串摩斯密码，你**换一套解码表**去读，读出来完全不同的意思。

**📝 考试这么考（你错过的题 Q13）：**
- ✅ *"reinterpret_cast makes a dangerous conversion explicit and only reinterprets bits, unlike a C-style cast."*
- ❌ *"reinterpret_cast is a portable and safe mechanism for converting any pointer type to any other."* —— 错！它**既不可移植也不安全**。

## 10. 静态方法 deserialize（static method）

**📖 原文：** *"Static methods... allow them to be invoked without creating an object of the class... The static deserialize method facilitates direct loading of tuples from disk data without the necessity to instantiate a page object beforehand."*

**💡 大白话：** 普通方法要**先有一个对象**才能调(`小明.吃饭()`)。**静态方法**属于**整个类**，**不用先建对象**就能调(`人类.总人口()`)。BuzzDB 用一个静态的 `deserialize` —— 不用先 new 一个空 Page 再填数据，**直接**从磁盘字节造出完整的页，一步到位。
> 🔵 类比：普通方法 = "找小明帮忙"(得先有小明)；静态方法 = "拨打 110"(不用先认识某个警察)。

## 11. 删除 + 内存↔磁盘同步（一致性）

**📖 原文：** *"When a tuple is deleted from a loaded page in memory, this change does not immediately reflect on disk... we must trigger the serialization process to write these changes to disk."*

**💡 大白话：** 你在**内存**里删了一个元组，但**没写回磁盘** → 再从磁盘读，删除根本没生效！这叫**持久性不匹配(persistence mismatch)**。解法：内存改完，**必须序列化写回磁盘**，让内存和磁盘一致。
> 🔵 类比：你在屏幕上(内存)删了一段文字，但**没按保存**，关掉再打开，那段文字还在(磁盘没变)。

## ✅ M3 一页总结

1. **DRAM 快易失贵 / 磁盘慢持久廉**——数据库的活就是用快内存掩盖慢磁盘。
2. **磁盘慢在寻道+旋转**；IOPS ∝ 1/延迟。
3. **序列化 = 把内存对象压扁成「长度+字节」的字节流**（指针没法存盘）；反序列化是反过来。
4. **Field 用 union 存多类型**；字符串要 new 在堆上、析构里 delete。
5. **裸指针四坑(漏/悬/双/权) → unique_ptr + RAII 自动救**。
6. **深拷贝=独立一份(安全)；浅拷贝=共享指针(危险)；unique_ptr 只能 move**。
7. **堆活到释放、栈函数返回即销毁**；别返回栈对象的引用。
8. **reinterpret_cast = 换一套解码表读字节**(危险)。
9. **内存改了必须写回磁盘**，否则不一致。
