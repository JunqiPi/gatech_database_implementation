## 1. 为什么要多线程：多核 CPU

**📖 原文：** *"increasing clock speeds led to excessive heat generation... hitting a thermal wall... dual core CPUs were introduced in 2005... A thread is a series of instructions listed for execution."*

**💡 大白话：** 以前 CPU 靠提**主频**变快,但 2004 年到 3.8GHz 撞上**热墙**(再快太热)。于是转向**多核**(如今 6–64 核)。要用上多核,数据库必须**多线程**并行(如两个用户的事务用两个线程同时跑)。
> 🔵 类比:主频=鼓点快慢;加核=多请几个鼓手同时打。**线程**=一串待执行的指令。

---

## 2. ⭐ 竞态条件（race condition）

**📖 原文：** *"when a thread performs an operation like bank balance plus equal to 10, this is not a single assembly instruction, but rather a sequence of three assembly instructions [load, add, store]."*

**💡 大白话：** `balance += 10` **不是一条指令**,是**三步**:① load(从内存读到寄存器)② add(+10)③ store(写回)。两个线程交错时**丢失更新**:
```
T1 load 1000
T2 load 1000      ← 还没等 T1 写回
T1 add→1010, store 1010
T2 add→1010(用的旧1000), store 1010   ← 覆盖!
结果 1010,应是 1020
```
> 🔑 **race condition = 结果取决于线程先后**;根因:read-modify-write 三步非原子,中途被打断。

---

## 3. mutex（互斥锁）

**📖 原文：** *"You can think of a mutex as a door lock to a room with a shared variable... The operations between the lock and unlock calls form a critical section. Only one thread can enter this section at a time."*

**💡 大白话：** **mutex** 像房间门锁,房里有共享变量。线程要进先拿锁,锁被占就等;进去独占操作,出来解锁。`lock` 和 `unlock` 之间是**临界区**,同时只一个线程进。底层用 **compare-and-exchange(比较并交换)** 原子指令实现。
> 🔵 把 `balance += 10` 包进临界区,三步就不会被打断。

**📝 考试这么考(测验 Q22)：**
- ✅ *"A mutex provides mutual exclusion for critical sections touching shared state."*
- ❌ *"A mutex ensures fairness across all threads."* —— 错！只互斥,**不保证公平**(谁先拿到不定)。

---

## 4. 粗粒度 vs 细粒度锁

**📖 原文：** *"using a single mutex significantly lowers concurrency... we can allocate a separate mutex for each bank account. This is known as fine-grained locking."*

**💡 大白话：**
| | 粗粒度(coarse) | 细粒度(fine) |
|:---|:---|:---|
| 做法 | 一把锁管所有账户 | 每账户一把锁 |
| 并发 | 差(操作账户1和5也抢同一把) | 好(不同账户并行) |
| 开销 | 锁少省内存 | 锁多、费内存 |
> 取舍:高竞争的部分用细粒度,低竞争用粗粒度就够。

---

## 5. 线程饥饿 + lock_guard + RAII

**📖 原文：** *"Thread starvation occurs when a thread holds a lock that other threads need, and those threads end up waiting indefinitely... std::lock_guard that automatically manages locking and unlocking."*

**💡 大白话：** **线程饥饿**:一个线程拿了锁**忘记解锁**(尤其复杂函数多出口/异常)→ 别人**永远等**。**`std::lock_guard`**(RAII):**构造时自动 lock、析构(出作用域)时自动 unlock**,即使抛异常也解锁,杜绝"忘记解锁"。
> RAII 三剑客:`lock_guard`(锁)、`unique_ptr`(内存)、`fstream`(文件句柄)。

**📝 考试这么考：**
- ✅ *"lock_guard (RAII) unlocks even on exceptional paths, reducing missed unlocks."*
- ❌ *"lock_guard guarantees fair lock-acquisition order."* —— 错!它保证**解锁**,不保证获取顺序公平。

## 6. 数据库配置（configuration）

**📖 原文：** *"Immutable parameters such as page_size are set at the time of database creation... mutable parameters like buffer_pool_size can be adjusted dynamically at runtime."*

**💡 大白话：** 配置=一组可调参数,DBA 调它们优化性能/成本:
- **page_size**:每页大小。**不可变(immutable)**——改它要 dump+reload 整库(影响磁盘布局)。
- **buffer_pool_size**:缓冲池大小。**可变(mutable)**——运行时动态调。
- 很多参数有**最优"甜点(sweet spot)"**(如 page_size 4KB 时吞吐峰值,两边都掉)。
- 应用类型:**OLTP**(短事务多)、**OLAP**(长分析查询)、Web(简单查询)——配置要按类型调。

**📝 考试这么考(测验 Q25/Q26)：**
- ✅ *"num_pages is `std::atomic` because threads read it for bounds checks while another extends the file."*（Q25）
- ❌ *"page_size can be changed at runtime without affecting the on-disk layout."* —— 错!page_size 不可变。

## 7. 调试（GDB / 原则）

**📖 原文：** *"GDB or the GNU Debugger is a tool for debugging C++ programs... compile the C++ code with the -g option... a practical debugging tip is to configure the size of the buffer pool to be very small, like ten pages."*

**💡 大白话：** **GDB** 调 C++(先 `-g` 编译加调试符号)。常用命令:`run / next / print / break / continue / backtrace / info locals`。**调试原则**:
- **小缓冲池调试**:设成 10 页(而非 1000),边界情况(耗尽/驱逐)更快出现、更好追踪。
- **模块化**(Wirth)、**文学化编程**(Knuth,代码先给人读)、**健壮性**(优雅应对磁盘 I/O 失败)。

## 📝 M6 出题风格英文速记（✅对的 / ❌陷阱）

| 考点 | ✅ 对的英文 | ❌ 陷阱 |
|:---|:---|:---|
| race condition | `+= 10` is load/add/store, can interleave & lose updates | "it's a single atomic instruction"(错) |
| mutex | mutual exclusion for critical sections | "ensures fairness"(错,Q22) |
| 锁粒度 | fine-grained → parallelism but more overhead | "fine-grained is always better"(错) |
| 配置 | page_size immutable; buffer_pool_size mutable | "page_size changeable at runtime"(错) |
| atomic | shared counter needs atomic to avoid races | 编造的理由(Q25 干扰项) |
| 调试 | small buffer pool surfaces edge cases sooner | 用大缓冲池调试(错) |

## ✅ M6 一页总结
1. 主频撞热墙 → **多核** → 必须**多线程**并行。
2. **race condition**:`+=` 是 load/add/store 三步,交错丢更新。
3. **mutex** 保护临界区(只互斥,不公平);底层 compare-and-exchange。
4. **粗粒度**(一把锁,并发差) vs **细粒度**(每项一锁,并发好但有开销)。
5. **lock_guard(RAII)** 自动解锁,防线程饥饿。
6. **page_size 不可变、buffer_pool_size 可变**;num_pages 用 atomic。
7. 调试用小缓冲池;模块化/文学化/健壮性。
