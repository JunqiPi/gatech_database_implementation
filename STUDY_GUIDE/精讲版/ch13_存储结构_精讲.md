# ch13 — Data Storage Structures（数据存储结构）精讲

> **模板**：每个知识点 = **【原句】**(章节英文原句) → **【侧重点 & 知识点】**(🔬英文 + 💡中文易懂)。
> ch13 对应 **Module 4–5**。考点:变长记录、**槽页结构**、缓冲管理(pin/lock)、列存。

---

## 1. 文件 = 记录 = 字段

**【原句】** *"The database is stored as a collection of files. Each file is a sequence of records. A record is a sequence of fields."*

**【侧重点 & 知识点】**
- 🔬 **EN:** Storage layers: database → **files** → **records** (rows) → **fields** (columns).
- 💡 **中文:** 数据库由文件组成,文件由记录(行)组成,记录由字段(列)组成。一层套一层。

---

## 2. 定长 vs 变长记录

**【原句】** *"Fixed-Length Records: store record i starting from byte n × (i – 1)... Variable-length attributes represented by fixed size (offset, length), with actual data stored after all fixed length attributes. Null values represented by null-value bitmap."*

**【侧重点 & 知识点】**
- 🔬 **EN:** **Fixed-length records** are easy to locate (record i at byte `n×(i-1)`). **Variable-length records** (e.g., strings) store variable parts as **(offset, length)** with data after the fixed part; nulls use a **null-value bitmap**.
- 💡 **中文:** 定长记录好定位(第 i 条 = 第 i×固定长度 字节)。变长记录(含字符串)用 **(偏移 offset, 长度 length)** 表示变长部分,实际数据放后面;null 用一个**位图(bitmap)** 标记哪些列是空。🔵 类比:固定大小的格子抽屉 vs 用"目录卡"记每件物品在哪、多大。

---

## 3. 槽页结构（Slotted Page）⭐⭐

**【原句】** *"Slotted page header contains: number of record entries, end of free space in the block, location and size of each record. Records can be moved around within a page... Pointers should not point directly to record — instead they should point to the entry for the record in header."*

**【侧重点 & 知识点】**
- 🔬 **EN:** A **slotted page** has a header with the **record count**, the **end-of-free-space pointer**, and a **slot directory** (location + size of each record). Records can be **moved within the page** (compaction); crucially, **pointers reference the slot entry in the header, NOT the record directly** — this indirection keeps slot IDs stable when records move.
- 💡 **中文:** 槽页=页头记"几条记录 + 空闲空间末尾 + 每条记录的(位置,大小)";记录可在页内挪动(压缩)。**关键:指针指向"页头里那条记录的目录项(slot)",不直接指记录** —— 这层**间接(indirection)** 让记录搬家时 slot 编号不变。
- 🔵 类比:储物间门口挂块牌子,写"1 号物品在 A 角占 2 格";你只认"1 号"(slot),物品在屋里随便挪,只更新牌子上的位置。(详见 M4 精讲)

## 4. 大对象（Large Objects）

**【原句】** *"Storing Large Objects (e.g., blob/clob types). Records must be smaller than pages. Alternatives: store as files... break into pieces and store in multiple tuples..."*

**【侧重点 & 知识点】**
- 🔬 **EN:** Records must be smaller than a page, so **large objects (blob/clob)** are stored as files, or split across tuples (e.g., Postgres TOAST).
- 💡 **中文:** 一条记录得比一页小,所以超大对象(图片/长文本 blob/clob)要么单独存成文件,要么切碎存多行(如 Postgres 的 TOAST)。🔵 呼应 Paper 4(Umbra)的"可变大小页"就是为了更好处理大对象。

---

## 5. 记录的文件组织方式

**【原句】** *"Heap – record can be placed anywhere... Sequential – store records in sequential order, based on the search key... Hashing – a hash function computed on search key."*

**【侧重点 & 知识点】**
- 🔬 **EN:** Ways to organize records: **heap** (anywhere there's space), **sequential** (sorted by search key), **multitable clustering** (related records of different tables together to cut I/O), **B+-tree**, and **hashing**.
- 💡 **中文:** 记录在文件里怎么排:**heap(堆)** 哪有空放哪;**sequential(顺序)** 按键排序;**multitable clustering** 把相关的不同表记录放一起(减 I/O);**B+树**、**哈希**(M7)。

---

## 6. 空闲空间图（Free-Space Map）

**【原句】** *"Free-space map: Array with 1 entry per block. Each entry... records fraction of block that is free... Free space map written to disk periodically, OK to have wrong (old) values for some entries."*

**【侧重点 & 知识点】**
- 🔬 **EN:** A **free-space map (FSM)** has one entry per block recording how full it is, so inserts can **quickly find a block with space** without scanning every block. It can be slightly stale.
- 💡 **中文:** FSM=每块一个条目,记这块多空,插入时**快速找"哪块有空"**,不用扫每一块。⚠️ 考点(测验 Q28):FSM 只管"找空位",**不解决页内碎片/压缩**。

---

## 7. 数据字典（Data Dictionary / 系统目录）

**【原句】** *"The Data dictionary (also called system catalog) stores metadata... names of relations, names/types/lengths of attributes, integrity constraints, physical file organization information."*

**【侧重点 & 知识点】**
- 🔬 **EN:** The **data dictionary (system catalog)** stores **metadata** = data about data: relation names, attribute types, constraints, where/how each relation is stored.
- 💡 **中文:** 数据字典(系统目录)存"元数据"(关于数据的数据):有哪些表、列的类型、约束、每张表怎么存在哪。🔵 类比:图书馆的"图书检索卡片柜"——不是书本身,是关于书的信息。

## 8. 缓冲管理:pin / 锁 ⭐

**【原句】** *"Pinned block: memory block that is not allowed to be written back to disk... Keep a pin count, buffer block can be evicted only if pin count = 0. Readers get shared lock, updates to a block require exclusive lock."*

**【侧重点 & 知识点】**
- 🔬 **EN:** The **buffer manager** caches disk blocks in memory. A **pinned** block can't be evicted; track a **pin count**, evict only when it's **0**. **Readers take a shared lock; writers take an exclusive lock** (one writer at a time; shared and exclusive can't coexist).
- 💡 **中文:** 缓冲管理器把磁盘块缓存内存。**pin(钉住)** 的块不能换出;用 **pin count** 计数,**=0 才能换出**。读用**共享锁**(多人可同时读)、写用**独占锁**(同时一个写)。
- ⚠️ 考点:**pin 防换出、latch/lock 防并发改**,两回事(示例 Q5)。

---

## 9. 缓冲替换策略 + 列存

**【原句】** *"Most operating systems replace the block least recently used (LRU)... LRU can be bad for some queries [e.g., sequential scans]... Toss-immediate strategy... Most recently used (MRU)."* 及 *"Column-Oriented Storage: store each attribute separately... Reduced IO if only some attributes are accessed... Improved compression."*

**【侧重点 & 知识点】**
- 🔬 **EN:** **LRU** is common but bad for sequential scans (use **toss-immediate** or **MRU** there). **Column-oriented (columnar) storage** stores each attribute separately → less I/O when reading few columns, better compression, vectorized execution → great for **OLAP**; row stores are better for **OLTP**.
- 💡 **中文:** LRU 常用但对顺序扫描差(该用 toss-immediate/MRU)——这就是 M5 的 2Q 思想。**列存(columnar)** 把每列分开存:只读几列时省 I/O、压缩好、能向量化→适合 **OLAP**;行存适合 **OLTP**。(呼应 Paper 2)
