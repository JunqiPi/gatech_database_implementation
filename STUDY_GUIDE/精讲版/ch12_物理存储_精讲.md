# ch12 — Physical Storage Systems（物理存储）精讲

## 1. 易失 vs 非易失存储

**【原句】** *"volatile storage: loses contents when power is switched off. non-volatile storage: contents persist even when power is switched off."*

**【侧重点 & 知识点】**
- 🔬 **EN:** **Volatile** storage (cache, main memory/DRAM) loses data on power-off. **Non-volatile** storage (SSD, magnetic disk, tape) keeps it.
- 💡 **中文:** **volatile(易失)**=断电就没(Cache、内存 DRAM);**non-volatile(非易失/持久)**=断电还在(SSD、磁盘、磁带)。

---

## 2. 存储层级（Storage Hierarchy）+ 访问时间

**【原句】** *"1–5 nanoseconds [cache]... 60–100 nanoseconds [main memory]... 20–100 microseconds [flash]... 5–10 milliseconds [magnetic disk]."*

**【侧重点 & 知识点】**
- 🔬 **EN:** A pyramid — faster = more expensive = smaller:
```
Cache         1–5 ns    ┐ volatile (primary)
Main memory   60–100 ns ┘
─────────────────────────
Flash/SSD     20–100 µs  ┐ non-volatile (secondary, on-line)
Magnetic disk 5–10 ms    ┘
Tape          (sequential, archival = tertiary, off-line)
```
- 💡 **中文:** 存储是金字塔,越往上越快越贵越小:Cache/内存(纳秒级)→ SSD(微秒级)→ 磁盘(毫秒级)→ 磁带(归档)。🔑 记数量级:内存 ~50ns、SSD ~50µs(差 ~1000 倍)、磁盘 ~5–10ms。

---

## 3. 磁盘为什么慢:寻道 + 旋转 + 传输 ⭐

**【原句】** *"Access time consists of: Seek time – time to reposition the arm over the correct track... Rotational latency – time for the sector to appear under the head... Data-transfer rate."*

**【侧重点 & 知识点】**
- 🔬 **EN:** HDD access time = **seek time** (move arm to the track, 4–10ms) + **rotational latency** (wait for the platter to spin the sector under the head, 4–11ms) + **transfer**.
- 💡 **中文:** 机械硬盘读一块要三步:**seek(寻道)** 磁臂移到对的磁道 + **rotational latency(旋转延迟)** 等盘片转到磁头下 + **传输**。🔵 类比:**老式黑胶唱片**找歌——先移唱针(寻道)、再等唱片转到那段(旋转延迟)。

---

## 4. 顺序 vs 随机访问 + IOPS（高频算题）⭐

**【原句】** *"Sequential access pattern... Disk seek required only for first block. Random access pattern... Each access requires a seek. I/O operations per second (IOPS)... 50 to 200 IOPS on current generation magnetic disks."*

**【侧重点 & 知识点】**
- 🔬 **EN:** **Sequential access** = only the first block needs a seek (fast). **Random access** = every block needs a seek (slow). **IOPS** = random block reads per second: **HDD 50–200**, **SSD ~10,000+**.
- 💡 **中文:** 顺序访问只第一次寻道,后面连着读(快);随机访问每次都要寻道(慢)。**IOPS=每秒随机读次数**:HDD 50–200,SSD 上万。
- 🔑 **考试公式:IOPS ∝ 1/延迟**。SSD vs HDD 的 IOPS 比 = HDD延迟 ÷ SSD延迟(注意 1ms = 1000µs)。例:8ms ÷ 80µs = **100×**。

---

## 5. MTTF（平均无故障时间）

**【原句】** *"Mean time to failure (MTTF) – the average time the disk is expected to run continuously without any failure. Annualized Failure Rate (AFR) = ((365×24) / MTTF) × 100%."*

**【侧重点 & 知识点】**
- 🔬 **EN:** **MTTF** = average time a disk runs before failing. **AFR** = annualized failure rate = (hours/year ÷ MTTF). More disks → higher chance *some* disk fails → need redundancy.
- 💡 **中文:** MTTF=一块盘平均能跑多久才坏。AFR=年化故障率。盘越多,总有一块坏的概率越高 → 所以要 RAID 冗余。

---

## 6. 闪存 / SSD 的脾气

**【原句】** *"NAND flash... requires page-at-a-time read... Page can only be written once. Must be erased to allow rewrite."*

**【侧重点 & 知识点】**
- 🔬 **EN:** **SSD/NAND flash**: random ≈ sequential read speed (no moving parts); but a page **must be erased before rewrite**, and erase blocks wear out → **wear leveling** spreads writes. SSD ~10,000 read IOPS, ~40,000 write IOPS (much higher with parallelism).
- 💡 **中文:** SSD 没机械臂,随机和顺序读差不多快。怪脾气:**写之前要先擦除**,而且每块擦写有次数上限(会"磨损")→ 用**wear leveling(磨损均衡)** 把写分散。

---

## 7. RAID（多盘冗余阵列）

**【原句】** *"RAID: Redundant Arrays of Independent Disks... high reliability by storing data redundantly... RAID Level 0: Block striping; non-redundant. RAID Level 1: Mirrored. RAID Level 5: Block-Interleaved Distributed Parity."*

**【侧重点 & 知识点】**
- 🔬 **EN:** **RAID** uses multiple disks for speed (**striping**) and reliability (**redundancy**): **Level 0** = striping, no redundancy (fast, no safety); **Level 1** = mirroring (full copy); **Level 5** = distributed parity (space-efficient redundancy); **Level 6** = double parity (tolerates 2 failures).
- 💡 **中文:** RAID=把多块盘组起来。**条带化(striping)** 提速、**冗余** 防丢。Level 0=纯提速不防丢;Level 1=镜像(整盘复制);Level 5=分布式校验(省空间);Level 6=双校验(能坏两块)。

---

## 8. 磁盘块访问优化

**【原句】** *"Buffering... Read-ahead: Read extra blocks... in anticipation. Disk-arm-scheduling algorithms re-order block requests so that disk arm movement is minimized (elevator algorithm)."*

**【侧重点 & 知识点】**
- 🔬 **EN:** Optimizations: **buffering** (cache blocks in memory), **read-ahead/prefetch** (read extra blocks expecting use), **disk-arm scheduling** (reorder requests to minimize arm movement, the "elevator algorithm"), and **contiguous file layout** (allocate by extents).
- 💡 **中文:** 优化手段:缓冲(把块缓存内存)、预读(预取后面的块)、磁臂调度(重排请求少跑路,像电梯)、文件连续存放(按 extent 区段)。🔵 注意:Paper 3 说 OS 的这套(尤其 LRU、预取)对数据库不够好,所以 DBMS 自己管。
