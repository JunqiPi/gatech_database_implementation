## 1. 为什么需要缓冲池

**📖 原文：** *"Axing data in memory typically takes around 50 nanoseconds. However, axing a page on an SSD... takes around 50 microseconds. So axing data from an SSD is roughly 1,000 times slower."*

**💡 大白话：** 内存 ~50ns、SSD ~50µs(**慢约 1000 倍**);内存 ~$10/GB、SSD ~$0.10/GB(**贵约 100 倍**)。所以把**热页缓存在内存(buffer pool)**、最小化慢磁盘 I/O。缓冲管理器**用 StorageManager** 加载/刷写页,自己专注"最大化命中(cache hit)"。
> 🔵 类比:常用工具放手边抽屉(内存),不常用的放仓库(磁盘);跑仓库一趟很慢。

---

## 2. 缓冲管理器实现（LRU list + page_map）

**📖 原文：** *"LRU list is a list of pairs containing a page ID and a unique pointer to a slotted page. It also maintains a map for quickly looking up pages in LRU list."*

**💡 大白话：**
- **LRU list**:一串 `(page_id, 页)`,按使用新旧排。
- **page_map**:`unordered_map<page_id, 位置>`,**快速查**某页在不在内存。
- **`get_page(id)`**:命中→更新顺序(touch)→返回;未命中→从磁盘 load(满了先 evict 一页)→返回。

---

## 3. LRU 替换策略

**📖 原文：** *"We use the least recently used or LRU eviction policy. This policy evicts the page that was least recently accessed."*

**💡 大白话：** LRU=换出**最久没被访问**的页(假设近期没用的、以后也不太会用)。`touch`=把访问的页移到链表头(最近用);`evict`=取链表尾(最久未用),**驱逐前先 flush 脏页到磁盘**(防丢改动)。

---

## 4. 策略接口 + FIFO（用多态实现可换策略）⭐

**📖 原文：** *"The policy interface... is an abstract base class with a set of virtual functions... The touch and evict functions are the essence of any cache eviction policy."*

**💡 大白话：**
- **抽象基类 `AbstractPolicy`**:声明**纯虚函数** `virtual void touch(PageId)` 和 `virtual PageId evict() = 0;`。
- FIFO / LRU / 2Q **继承**它并 override。BuffMgr 持一个 `Policy*` 指针 → 通过 **vtable 运行时分派**。
- **FIFO**:换出**最早进来**的页(访问**不**重排);**LRU** 比 FIFO 好,留住近期热页。

**📝 考试这么考(你错的 Q15/Q18/Q24)：**
- ✅ *"A polymorphic `Policy*` lets you swap FIFO/LRU/2Q at BOTH compile time and runtime (point it at a different object), no relinking."*（Q15/Q24）
- ❌ *"Marking `evict()=0` enables compile-time binding and removes virtual-call overhead."* —— 错(Q18)！`=0` 是**纯虚函数** → 类变**抽象**(不能实例化)+ 调用走 **vtable 运行时分派**(开销还在)。

---

## 5. policy vs mechanism（策略 vs 机制）

**📖 原文：** *"policy uses mechanism is a fundamental concept in system design. Policies determine what action should be taken while mechanisms determine how these actions are executed."*

**💡 大白话：**
- **policy(策略)** = 决定"做什么"(该踢哪页)。
- **mechanism(机制)** = 决定"怎么做"(怎么把页写到磁盘)。
- 分离后:换策略不用改机制。
> 🔵 类比:policy="决定先扔哪件旧衣服";mechanism="怎么把衣服打包扔出去"。换决策标准,打包方式不变。系统设计中策略比机制更"经得起时间"。

---

## 6. ⭐ 缓冲池冲刷（flooding）+ 2Q 策略

**📖 原文：** *"when the database performs a sequential scan, the scan can potentially flood the buffer pool with less important pages... The two Q policy... uses two separate queues, a FIFO queue for read once's pages... and a separate LRU queue for frequently accessed hot pages."*

**💡 大白话：**
- **问题**:**顺序扫描**(扫全表)读入大量"扫一次就不用"的冷页,**LRU 把它们当'最近用过'留着,挤走真正的热页**(页 1、页 2 反复被踢→反复 miss)。
- **2Q 解法**:两个队列——
  - **FIFO 队列**:放"扫一次"的冷页(新页先进这)。
  - **LRU 队列**:放热页(页**第二次被访问**时**晋升**过来)。
  - **驱逐优先踢 FIFO 队列**(冷页),保护 LRU 的热页。FIFO 空了才踢 LRU 尾。
- 例:同一访问序列,LRU 10 次 miss,2Q 只 6 次。
> 🔵 类比:音乐推荐——FIFO 队=你随便听过一次的新歌;LRU 队=你反复听的爱歌。要腾位先删"听过一次"的,保住爱歌。

**🌟 Paper 3 关联:** Stonebraker 早就说 OS 的 LRU 对顺序扫描差,该 **toss-immediately(用完即扔)**——2Q 就是这思想。

---

## 7. 其它策略（LFU / ARC）

**📖 原文：** *"Least frequently used or LFU keeps frequently used pages... Adaptive replacement cache or ARC... dynamically balances between LRU and LFU."*

**💡 大白话：** **LFU(最不常用)** 留访问**频率**高的页,缺点是对模式变化反应慢(过去常用现在没用的也留)。**ARC** 自动平衡 LRU(recency)和 LFU(frequency),缺点是实现复杂。

---

## 8. pin / latch（PA2 + 示例 Q5）⭐

**📖 原文(ch13)：** *"Keep a pin count, buffer block can be evicted only if pin count = 0. Readers get shared lock, updates to a block require exclusive lock."*

**💡 大白话：**
- **pin(钉住)** 一页 = 读写前钉住、**防止它被驱逐**;用 **pin count** 计数,**=0 才能驱逐**。
- **共享锁(shared)** 给读者(多人可同时读)、**独占锁(exclusive)** 给写者(同时一个)。
- ⚠️ **pin 防驱逐、latch 防并发改**,两回事!**pin count=0 的帧随时被驱逐**,裸指针就悬空了。

**📝 考试这么考(测验 Q5、示例 Q5)：**
- ✅ *"A nonzero pin count prevents eviction; you still need the frame's latch while touching its bytes."*
- ❌ *"Holding only the latch (pin count=0) is enough to prevent eviction."* —— 错！pin=0 仍可被驱逐。
- ❌ *"On SSDs, buffer-pool sizing isn't critical."* —— 错(Q5)！SSD 仍慢于 DRAM。

## 📝 M5 出题风格英文速记（✅对的 / ❌陷阱）

| 考点 | ✅ 对的英文 | ❌ 陷阱 |
|:---|:---|:---|
| 多态策略 | swap policy at compile AND runtime via `Policy*` | "runtime needs relinking"(错,Q15/24) |
| 纯虚函数 | `=0` → abstract class + runtime vtable dispatch | "=0 enables compile-time binding"(错,Q18) |
| SSD 缓冲 | buffer-pool sizing still matters (SSD < DRAM) | "sizing not critical on SSD"(错,Q5) |
| 2Q | evict FIFO queue first to protect hot pages | "evict LRU queue first"(错) |
| pin/latch | pin prevents eviction; latch prevents concurrent modify | "latch alone prevents eviction"(错) |
| 脏页 | flush dirty page before eviction | 直接丢弃脏页(错,丢数据) |

## ✅ M5 一页总结
1. 内存比磁盘快~1000 倍 → **缓冲池**缓存热页、最小化 I/O。
2. 实现:**LRU list + page_map**;get_page 命中更新顺序、未命中 load(满则 evict)。
3. **LRU/FIFO/2Q** 用**抽象基类+纯虚函数**实现 → **运行时**多态可换(编译期+运行期都行)。
4. **`=0` 纯虚 = 抽象类 + 运行时 vtable 分派**(不是编译期绑定!)。
5. **policy(做什么) vs mechanism(怎么做)** 分离。
6. **顺序扫描冲刷缓冲池** → **2Q**(FIFO 冷页队 + LRU 热页队,驱逐先 FIFO)。
7. **pin 防驱逐(count=0 才驱逐)、latch 防并发改**——别混。
