## 1. 并行建索引 + 哈希表的 race condition

**📖 原文：** *"Thread safety is a property of a data structure that guarantees safe execution by multiple threads at the same time without causing any data loss... Thread 1 and Thread 2 simultaneously try to insert the keys 15 and 25... the hash value is 5."*

**💡 大白话：** 单线程逐页建索引慢,多核上把页**分给多线程并行**。但哈希表**不是线程安全**的会**丢数据**:
```
两线程都插入 hash 到 slot 5 的 key(15 和 25):
T1 探测 slot 5,发现空 ──(切换)
T2 探测 slot 5,也发现空
T1 存 15 到 slot 5
T2 存 25 到 slot 5   ← 覆盖了 15!丢数据
```
> 🔑 **thread-safe(线程安全)** = 多线程同时访问也不丢数据/损坏。

---

## 2. 用 mutex 串行化（最粗暴的修法）

**📖 原文：** *"To address this race condition, we need to use a mutex... only one thread can modify the index at any given time."*

**💡 大白话：** 用一个 **index mutex** + `lock_guard`:谁改索引前先拿锁。修复后:T1 拿锁插 15 到 slot 5 → 解锁 → T2 拿锁,发现 slot 5 占了 → 探测到 slot 6 插 25。**两个都对,无丢失**(谁先谁后都正确)。
> ✅ 全局锁**保证正确**,但所有线程串行 → **并发差**(退回单线程)。

---

## 3. ⭐ 细粒度锁（每槽一锁）+ 为什么 vector<unique_ptr<mutex>>

**📖 原文：** *"we introduce fine-grained locking. This method involves associating a separate mutex with each slot... Why do we use a vector of unique pointers to mutexes instead of... a vector of mutexes? ...mutex objects are non-movable and non-copiable."*

**💡 大白话：** **细粒度锁**=**每个槽一把 mutex**。T1 锁 slot 2、T2 锁 slot 7 → **并行**,互不等。
> ⚠️ **高频考点:为什么用 `vector<unique_ptr<mutex>>` 而非 `vector<mutex>`?**
> `std::mutex` **不可移动、不可拷贝**(设计如此);但 `std::vector` 扩容要**移动元素** → 矛盾!解法:存**指向 mutex 的 unique_ptr**,扩容时只移动**指针**,不移动 mutex 本身。
- 取舍:细粒度提并发,但锁多→开销/内存增加。要平衡(高竞争处细粒度、低竞争处粗粒度够)。

---

## 4. ⭐ shared_mutex（读多场景提速）

**📖 原文：** *"std::shared_mutex... enabling multiple threads to hold a read lock simultaneously while still ensuring exclusive access for threads performing write operations... Write operations require an exclusive lock via std::unique lock... shared lock is utilized [for reads]."*

**💡 大白话：** 普通 mutex 对一个槽**同时只一个线程**(不管读写),浪费并发(多个读本可同时)。**`std::shared_mutex`** 区分读写:
- **写**:`std::unique_lock`(独占,同时一个,写时无读者)。
- **读**:`std::shared_lock`(共享,**多读者可同时**,只要没人写)。
> 效果:读多时,16 个线程能**同时读**同一槽(线程安全),读吞吐大增。
> 🔵 类比(Paper 4 versioned latch):独占=写、共享=多读、乐观=读不上锁只记版本号。

**📝 考试这么考：**
- ✅ *"Writers use `unique_lock` (exclusive); readers use `shared_lock` (multiple concurrent readers)."*
- ❌ *"shared_mutex allows only one thread at a time regardless of read/write."* —— 错!读可并发。

---

## 5. 并发协议对比（模拟器）

**📖 原文：** *"the global mutex protocol takes 30 steps. The mutex per slot protocol takes 21 steps, and the shared mutex per slot protocol only takes 15 steps."*

**💡 大白话：** 同一组操作,需要的**逻辑时间步**(越少越好):
| 协议 | 步数 | 为什么 |
|:---|:---:|:---|
| 全局 mutex | 30 | 所有访问串行 |
| 每槽 mutex | 21 | 不同槽并行 |
| 每槽 shared_mutex | **15** | 不同槽并行 + 同槽多读并发 |
> 🔑 粒度越细 + 区分读写 → 并发越高 → 步数越少。**读多负载下,每槽 shared_mutex 最快。**

---

## 6. TOCTOU 竞态（unfix_page，测验 Q20）⭐

**📖 原文(题目)：** *"unfix_page checks the frame's exclusive flag after dropping the global buffer pool lock."*

**💡 大白话：** **先放锁、后检查共享状态**=经典 **TOCTOU(time-of-check / time-of-use,检查时/使用时)** 竞态——放锁后状态可能被别的线程改:另一线程可能 fix_page 该帧改标志、帧可能被驱逐、元数据被覆盖。**后果是悄悄的数据损坏,不是内核 panic。**
> 🔑 教训:**"检查 + 操作"必须在同一把锁的保护下**完成。

**📝 考试这么考(测验 Q20,你错过)：**
- ✅ *"Dropping the lock then checking shared state is a TOCTOU race; the harm is silent data corruption."*
- ❌ *"It immediately triggers a kernel-level thread panic."* —— 错!OS 不会 panic。

## 📝 M8 出题风格英文速记（✅对的 / ❌陷阱）

| 考点 | ✅ 对的英文 | ❌ 陷阱 |
|:---|:---|:---|
| 并发插入 | unsynchronized → one overwrites the other (lost data) | "OS panics"(错) |
| vector 装锁 | `vector<unique_ptr<mutex>>` (mutex non-movable) | `vector<mutex>`(错,编译/语义问题) |
| shared_mutex | writers exclusive, readers shared (concurrent) | "one at a time regardless"(错) |
| 协议性能 | shared-per-slot < per-slot < global (steps) | 顺序反了(错) |
| unfix race | check-after-unlock = TOCTOU, silent corruption | "kernel panic"(错,Q20) |

## ✅ M8 一页总结
1. 并行建索引时哈希表**不安全**:两线程抢同一空槽→**覆盖丢数据**。
2. **mutex 串行化**保证正确,但并发差。
3. **细粒度每槽锁**提并发;用 **`vector<unique_ptr<mutex>>`**(mutex 不可移动)。
4. **shared_mutex**:写用 `unique_lock`(独占)、读用 `shared_lock`(多读并发)→读多场景快。
5. 协议性能:**每槽 shared_mutex < 每槽 mutex < 全局 mutex**(步数,越少越好)。
6. **先放锁后检查 = TOCTOU 竞态**,后果是数据损坏(不是 panic)。
